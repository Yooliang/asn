# 設定值清單

> 這份是 ASN 所有「使用者可以改的設定」的總表：每個設定在設定頁哪一類、畫面上怎麼寫、什麼型態、預設值是什麼、存在哪裡、電腦／手機／網頁各有沒有、誰會讀它。
> 用途：領隊排「新設定放哪一類」之前先看這份；開發夥伴新增或搬移設定時，**同一張 PR 要一起更新這份**（開發紀律第六節）。
> 寫這份的依據是 main 的程式（`90de829e`，0.2.36），不是舊的盤點。預設值都附了程式裡實際的位置。
> 守門測試：`relay/asn/test/settings-list.test.mjs`。它直接從程式取得「電腦設定頁會送出的每個指令」「手機偏好的每個鍵」「設定頁的每個分類」，在這份清單找不到就變紅；清單裡寫了程式已經沒有的，也會變紅。

## 怎麼讀、怎麼維護

- 每一節是設定頁的一類；每個表格列是一個設定（或一組按同一件事的按鈕）。
- 第一欄「指令／鍵」是守門測試認的標記，**每個標記整份清單只能出現一次**，用反引號包起來：
  - `skin` 這種不帶前綴的＝電腦設定頁元件送出的指令（`SETTING_OPS`，在 `ui/lib/settings-panel.mjs`）。
  - `prefs.vibrateMsg` 這種＝手機偏好的鍵（`DEFAULT_PREFS`，在 `ui/lib/mobile.mjs`）。
  - `cat.look` 這種＝設定頁的分類（只出現在最前面的分類總表）。
  - `flag.AGENT_INSTALL_UI` 這種＝寫死在程式裡的旗標。
  - `app.xxx` 這種＝不走上面三條路、但使用者看得到也改得到的設定（例如帳號層的設定、手機獨有的名字欄）。測試只檢查它整份只出現一次。
- 新增設定：先決定放哪一類（看下面的分類總表與各節現有的設定），再在那一節加一列；新的電腦指令要加進 `SETTING_OPS`，新的手機鍵要加進 `DEFAULT_PREFS` 與 `normalizePrefs`，兩邊都會被測試逼著登記。
- 「預設值」欄的字，跟程式裡的標籤逐字相同的（例如選單的選項名稱），測試會拿程式的標籤去比；改預設就要改這欄。
- 「誰會讀它」每列至少一個**錨點**，寫法是 `《檔案＃一段程式內容》`，路徑從 `relay/asn/` 起算，內容用函式名、常數名或一小段原文。測試會打開那個檔案，確認這段內容真的在裡面；程式改名或搬走時它會變紅，照新的位置改這一欄。不再寫行號（行號會漂移：`bridge-launch` 曾寫 `mod.rs:110`，實際預設在 `mod.rs:79`），其他欄（預設值、存在哪裡）也一樣，寫了 `檔案:行號` 會被擋下。
- 「預設值」欄：能從程式取得的，測試逐項比對（選單的標籤、數字、開關、Rust 的常數與預設初值）；**比不了的**在該欄結尾標 `〔人工：原因〕`，原因要寫為什麼取不到（例如「值來自系統登錄」）；本來就沒有預設值的寫「不適用」開頭。三者都不是就會被擋下。
- 「電腦／手機／網頁」三欄**不准空白**。有就寫「有」（括號可補說明）；沒有就寫「無：原因」或「無（原因）」，原因要寫成使用者或開發者看得懂的話，不能只寫「無」或「同上」。
- 一份文件有好幾張表，各表由各自的測試守：表頭有「指令／鍵」的表（這份清單的主體）由 `settings-list.test.mjs` 管；「環境變數」節由 Rust 測試管（#2163）；之後加的表（例如前端旗標，#2321）表頭不要用「指令／鍵」，各用各的測試，互不干擾。
- 「存在哪裡」的說法：
  - 「這台自己」＝只存在這台設備的本機，別台看不到。
  - 「所有設備共用」＝存在後台（帳號層），同一個帳號的每台設備都看得到。
  - 本機的檔案都在這台的 ASN 資料夾裡（電腦版 `asn-<名稱>.json`、各自的 `*.json`；手機版在手機的 me 存檔）。
- 「網頁」：目前 repo 裡**沒有網頁版的畫面**；後台只做了網頁登入的第 0 階段（`docs/AUTH.md` 的「網頁登入」），沒有設定頁。所以網頁欄一律寫「無（尚無網頁版）」；網頁版做出來時，先回來看哪些設定要補。

## 環境變數

環境變數不是設定頁的設定，而是部署、測試或維運時從外面設給程式的值。這一節列出電腦版與命令列（Rust，`relay/asn/src-tauri/src`）讀到的每一個 `ASN_*`，來源是 `src-tauri/src/flags/table.rs` 的登記表，由 Rust 測試逐列比對：程式裡多一個沒登記的名字、登記了卻已經沒人讀、這份表和登記表對不上，都會變紅。新增環境變數要在登記表加一列、再回來更新這一節。

## 查不到或有疑問的地方

這一節是寫這份時沒辦法從程式確定的，留給下一個人補：

- **自動啟動的預設值**：程式裡沒有「預設值」，只讀系統現況；也沒找到安裝程式替使用者預先勾選的地方，所以寫「沒人設過就是關」，並標〔人工〕（測試比不了）。
- **`bridge-launch` 的預設有兩個說法**：程式預設關（《src-tauri/src/bridge/mod.rs＃impl Default for BridgeSettings》），新裝的電腦才在第一次啟動時寫成開（《src-tauri/src/first_run.rs＃s.allow_remote_launch = true》）；舊電腦升級上來沒有被改。畫面說明寫「新裝的電腦預設打開」是對的，但只看 `read_settings` 會誤以為預設是關。這兩處現在都由測試核對。
- **三平台不一致、程式裡沒記原因的**（不是平台本來就沒有的功能，依開發紀律第一節應該一起做或說明）：手機沒有「顯示正在聽的歌」、手機沒有顯示自己指紋 QR、手機沒有「刪除 Claude 帳號」與 Grok 切換、手機沒有分頁與分組選項（固定依設備）、手機沒有語音念出與設定、手機沒有「檢視記錄」。
- **同一件事兩邊畫面文字不同**：帳號名稱欄電腦寫「帳號名稱」、手機寫「我的名字」（`ui/lib/login-panel.mjs`、`ui/m.html`）。
