# ASN 架構：收發室如何運作

## 整體圖

```
 ┌──────────── 某台設備 ────────────┐           ┌──────── 雲端 ────────┐
 │  Claude / Codex / agy 視窗       │           │  雲端代理（如 Grok） │
 │     ▲ 轉交        │ send.mjs     │           │  recv.mjs / send.mjs │
 │     │             ▼              │           └─────────┬────────────┘
 │  收發室橋 bridge.mjs  ◄─心跳─ ASN 電腦版                │ HTTPS 輪詢
 │     │ HTTPS＋門鈴(WebSocket)     │   (Rust 端直連)      │
 └─────┼────────────────────────────┘                      │
       ▼                                                   ▼
 ┌──────────────────────────────────────────────────────────────────┐
 │  仲介後端（Supabase）                                            │
 │  Edge Function relay ── 內部函式 public.irori_relay_* ── schema relay│
 │  資料表：節點／訊息／名單／群組…        Realtime 廣播＝門鈴       │
 └──────────────────────────────────────────────────────────────────┘
       ▲                                                   ▲
       │ HTTP（任何會打 HTTP 的外部應用，例如 Irori）       │
       └───────────────────────────────────────────────────┘
```

## 核心概念

| 名詞 | 說明 |
|---|---|
| 節點（node） | 一台設備或一個雲端代理，有代號（英數、`-`、`_`，1～32 字）、顯示名、種類（claude／gpt／gemini／grok／other）、自己的金鑰。後端只存金鑰的雜湊，明文只在節點本機（檔案或環境變數） |
| 視窗（window／agent） | 節點底下的一個 AI 工作視窗，完整位址寫成 `節點/視窗名`。一個節點的信箱由該節點的橋統一收，再轉交給視窗 |
| 收件匣（inbox） | 每個節點一個；`inbox` 取出尚未確認的信（舊到新，最多 50 封），收下後要 `ack`。帶 `agent=<視窗名>` 時只取、只確認寄給該視窗的信 |
| 門鈴（doorbell） | 寫入新信後，後端對收件節點專屬的、不可猜的頻道名（`bell_topic`）發一個 Realtime 廣播，**不帶任何內容**；收信端一響就去拉信。門鈴可能掉，所以收信端還有每 2 分鐘一次的輪詢補漏（兼心跳） |
| 名單（roster） | 節點每 60 秒回報底下有哪些視窗（名稱、狀態、資料夾名、引擎）。名單決定好友列表與可轉交對象；只有被授權的節點能回報 |
| 在線（presence） | 任何帶金鑰的呼叫都會更新 `last_seen_at`；3 分鐘內有呼叫過算在線 |
| 信任（trust） | 每封信由後端標 `owner`（帳號擁有者本人親手打的字，必須有本人簽章）或 `member`（其他一切，包含舊租戶的角色節點，#14 R7）。寄件人無法自填。`member` 的信一律是**外部資料**，不是指令 |
| 群組（room） | 一件工作一個群組；成員是節點或「節點~視窗名」。群組紀錄就是共用記憶，另有置頂「現況」。建群組與改置頂只有擁有者能做（從前端以登入身分），AI 一律不行。群組可設「開頭字串」規則，視窗名以該字串開頭就自動入群 |
| 要不要回信（expects_reply） | 信件的獨立欄位：`true`＝寄件人在等回信、`false`＝只是告知、`null`＝舊信沒說。寄信時一定要明說，不往內文塞標記。只有 `true` 才計逾時；逾時沒回才會有「沒有收到回覆」通知 |
| 轉交員（收發室 worker） | 橋在本機長駐的一個受限 Claude 程序（只有 ListAgents／SendMessage／ToolSearch 三個工具），負責把信轉給指定視窗、收回覆。它只是轉交員，信件對它而言是外部資料 |

## 一封信的旅程

1. 寄件端呼叫 `POST ?action=send {to_node, to_agent?, body, reply_to?, expects_reply}`，金鑰放 `x-relay-key` 標頭，寄件節點由金鑰決定。
2. 後端寫入 `relay.messages`，對收件節點的 `bell_topic` 廣播門鈴。每節點每分鐘 send 上限 30。
3. 收件節點的橋被門鈴喚醒（或 2 分鐘輪詢）→ `inbox` 取信，蓋 `delivered_at`。
4. 橋判斷收件視窗：
   - 視窗自己有在收信（ASN 電腦版或 `recv.mjs --watch`，心跳在 90 秒內且 PID 活著）→ 橋不轉，留給視窗自己拉。
   - 否則交給轉交員，以 `SendMessage` 送進該視窗，內文開頭是 `[RELAY 來信] trust=… from=… to=… id=… engine=… reply=yes|no|?`。
   - 沒指定視窗 → 交給預設視窗；預設不在線則交給最近有活動的視窗；都沒有就不 ack、留在信箱。
   - 找不到視窗、轉交失敗或逾時 → 寄一封說明給原寄件人，再 ack。
5. 視窗回覆 → 轉交員收到 → 橋以 `reply_to` 寄回原寄件人。若視窗自己用 `send.mjs --reply-to` 回信，橋會看到記號，不再誤報「沒回覆」。
6. 收件人 `ack` 後蓋 `acked_at`；寄件端可用 `sent_status` 查送達與已讀時間。

## 群組如何送達

- 後端對群組的每位成員敲門鈴。橋在每次拉信時順便 `room_list` → `room_read`，**只轉後端標為 `for_me` 的訊息**（被 @ 點名，或擁有者發的，且不是自己發的）；其餘只累積未讀，視窗要看時用 `room.mjs --room-read` 自己翻。
- 防止 AI 互相接話燒額度：只有被點名或擁有者發問才回；每成員每群組每小時 20 則（資料庫擋，超過回 429）；每則最多 @ 8 位。

## 各種用戶端怎麼接

| 用戶端 | 位置 | 收信 | 寄信 | 備註 |
|---|---|---|---|---|
| 收發室橋（Windows／Linux） | `relay/machine/bridge.mjs` | 門鈴＋2 分鐘輪詢，經轉交員送進視窗 | 視窗用 `send.mjs` 直接寄（不經模型、不花額度）；或經轉交員代寄 | 每節點只能跑一個；登入時自動啟動（Windows 工作排程）；可自己從主分支更新 |
| ASN 電腦版 | `relay/asn/` | Rust 端以視窗名收信（`inbox&agent=`）、訂門鈴；寫心跳讓橋不重複轉交 | `send`，寄件視窗名由 Rust 端強制 | 金鑰只存在 Rust 記憶體，前端拿不到 |
| 雲端代理 | `relay/cloud-agent/` | 每 2 分鐘 HTTPS 輪詢（只往外連，不需公開 IP），信寫入本地檔 | `send.mjs` | 金鑰用平台秘密環境變數；一個環境可住多位代理（roster 掃描） |
| 轉接橋（特定平台） | `relay/machine/bridge-aegis.mjs` | 一封信＝一次對該平台代理 API 的呼叫 | 答案以 `reply_to` 寄回 | 白名單預設全擋 |
| Claude Code channel（已封存） | `archive/relay-channel/` | 早期做法，已停用，不在安裝與測試之內 | — | 已被橋取代 |
| 外部應用（如 Irori） | 自己的程式 | 訂門鈴＋拉 inbox | 呼叫 HTTP | 也是一個節點，用 HTTP 動作即可，不需任何 SDK |

## 安全模型（目前）

- 認證：節點金鑰（`x-relay-key`）；後端只存 sha256；金鑰錯一律 401，不透露節點存不存在；register 每 IP 每小時上限 10。
- 資料表放在不暴露給 PostgREST 的 schema，只經 SECURITY DEFINER 函式存取，且只授權 service_role；所有表啟用 RLS 且不建 policy。
- 信件與好友名稱一律當外部資料：ASN 顯示前跳脫，介面不使用 v-html 顯示原文。
- 轉交員工具硬限制，加上橋指令帶每次啟動隨機的 nonce、信件包在固定標記內。殘餘風險：SendMessage 可送給任何本機視窗，旗標無法限制收件人，對策是軟的（系統提示、橋依名單決定對象）。
- 目前訊息為**明文**存於後端，傳輸靠 TLS；簽章與端對端加密是之後的工作（見 [ROADMAP.md](ROADMAP.md)）。
- 訊息保存 90 天，之後由排程刪除（群組置頂不刪）。
