# 畫面規範

> #2105 第 1 步：**先寫規範，擁有者看過才動程式。** 擁有者 11-22 已看過並回「照建議」，第七節四點定案；這份是定案版（2026-11-22，asn西川整理）。
> 文字用字的規則（不放開發者細節、按鈕用動作說法）在 [開發紀律.md](開發紀律.md) 第四節，這份管的是「長什麼樣、放哪裡、尺寸多大」。
> 第一個範例是 #2111 的設備列與按鈕（擁有者 11-22 定案的「按鈕樣式與顏色規則」），本文的按鈕規則與它一致。

## 一、為什麼要有這份

擁有者 11-22：「按鈕胡亂排，一下子排在文字後面、一下子排在別處，按鈕大小不一」。11-22 唯讀盤點的現況：

- 按鈕主 class 電腦 `aero-btn`（184 處）、手機 `m-btn`（85 處），另有約 37 種；`aero-btn` 有 14 條依位置覆寫的規則，出現 7 種 padding、4 種字級。
- 同一類動作位置不一：「重試」接在文字後、「重新檢查」在標題右、「立即檢查」在列首、「下載語音辨識」獨立一列。
- 「確定／取消」順序不一（3 處確定在前、1 處取消在前）；確認有 4 種寫法；錯誤字 class 16 種以上、空狀態 10 種、載入中 4 種寫法。
- 字級約 30 種、寫死的 px 約 3300 個，電腦與手機各一份 CSS。

目標：同一類東西，在每一頁、電腦與手機，長得一樣、放的位置一樣。

## 二、按鈕

### 2-1 三級

| 級別 | 用在哪 | 樣子 |
|---|---|---|
| 主要 | 一個區塊裡「最想讓人按的那一個」，例如「進行安裝」「同意並安裝」「儲存」 | 實心強調色。**一個區塊最多一個。** |
| 次要 | 一般動作，例如「重新檢查」「加入」「移除」「切換」 | 預設的白底框線鈕 |
| 文字鈕 | 不會造成後果的小動作，例如「重試」「複製」「展開」 | 沒有框，只有字與底線／強調色 |

特殊色（只給下面這些用途，不准挪作他用）：

- **危險（紅）**：不可復原的動作（移除、刪除、結束），一定要原位確認。
- **使用中（深灰底白字）**：表示「現在就是這個」，不能按、不寫原因。
- **黃色**：只給「重新登入」用。
- **不能按（虛線框、淡色）**：不能做的動作，原因寫在旁邊那一行（見 4-2），不是按了才跳框。

### 2-2 尺寸（固定，不依位置覆寫）

| | 電腦 | 手機 |
|---|---|---|
| 一般鈕高度 | 28px | 40px |
| 一般鈕左右留白 | 12px | 14px |
| 設備列上的鈕 | 92×28 | 100×40 |
| 字級 | 12px | 14px |
| 兩顆鈕的間距 | 8px | 8px |

- 不再有「在這個容器裡縮小一點」「在這一頁字級改小」的覆寫；真的需要特別尺寸，先改規範。
- 手機最小觸控目標 40px 高。

### 2-3 位置

1. **鈕一律在它管的東西的右邊或下方的右側，不接在文字後面。** 標題＋說明＋右側動作的列，動作靠右、同一欄。
2. 一列有多顆鈕時，**最不具破壞性的在左、最主要的在右**；取消在左、確定在右（擁有者 11-22 定案，見第七節）。
3. 窄版（電腦 560px 以下）與手機：鈕一律靠右、不撐滿整列；放不下才換到下一行，換行後仍靠右。
4. 同一頁、同一類的動作，用同一個位置。

### 2-4 文字

按鈕文字用動作說法，不用疑問句，不加括號自白（開發紀律第四節）。取消一律寫「取消」，需要說清楚時寫「先不要」；確定鈕寫它會做的事（「同意並安裝」），不寫「確定」。

## 三、版型

| 版型 | 用在哪 | 規則 |
|---|---|---|
| 區塊標題列 | 設定頁各區塊 | 左：標題；右：這個區塊的動作（例如「重新檢查」）。副標說明在標題下一行，灰字。 |
| 一台一列 | 設備、帳號底下的設備、工具清單 | 左：名稱（有原因就寫在名稱下方一行）；右：固定欄寬的鈕。 |
| 表單列 | 設定項 | 左：名稱與說明；右：控制項（開關、選單、輸入框）。窄版改上下排。 |
| 清單列 | 資料夾清單等 | 左：內容；右：每列一個「移除」。清單下面一列放「加入」，靠右。 |
| 動作列 | 對話框、原位確認的底部 | 靠右，順序見 2-3。 |

## 四、確認與狀態

### 4-1 確認一律原位

- 按下會有後果的動作，**確認出現在那顆鈕所在的那一列下方**，不跳框、不擋住畫面。
- 確認的內容只說「會發生什麼」；兩顆鈕：取消（左）、同意並做這件事（右，主要鈕）。
- 「取消」不呼叫任何後端；進行中不重複打開。
- 只有「一定要看完才能繼續」的才用對話框（例如登入授權碼），不能因為「方便」就跳框。

### 4-2 不能做的事

不把鈕藏起來，也不是按了才說「不行」：鈕畫成「不能按」樣式，原因寫在**名稱下方那一行**（一台一列的版型）或鈕旁邊，一句白話（要說「怎麼辦」，例如「ASN 尚未開啟」「到那台重新登入這個帳號」）。

### 4-3 四種狀態行（一種寫法各一種）

| 狀態 | 位置 | 樣子 | 文字 |
|---|---|---|---|
| 進行中 | 觸發它的那一列下方 | 灰字＋小轉圈 | 「正在 XX…」，不寫「請稍候」 |
| 成功 | 同上 | 綠字，數秒後自己消失（成功 4 秒） | 一句：做了什麼 |
| 失敗 | 同上 | 紅字，留著直到下次操作 | 一句：發生什麼、怎麼辦；原文只進 ui.log |
| 空 | 該區塊內 | 灰字 | 一句：現在沒有什麼，下一步是什麼（有動作就附鈕） |
| 讀不到 | 該區塊內，**不准整塊消失** | 灰字＋「重試」文字鈕 | 一句：讀不到什麼 |

「載入中」統一寫「正在讀取…」。

## 五、間距與字級（design token，電腦與手機共用）

不再寫死 px，改用變數（放在共用的 CSS 變數表）：

| 變數 | 值 | 用在 |
|---|---|---|
| `--sp-1` | 4px | 圖示與文字、緊貼的小元素 |
| `--sp-2` | 8px | 鈕與鈕、列內元素 |
| `--sp-3` | 12px | 列與列、區塊內邊距 |
| `--sp-4` | 16px | 區塊與區塊 |
| `--sp-5` | 24px | 頁面段落 |
| `--fs-1` | 11px（手機 12px） | 輔助說明、標籤 |
| `--fs-2` | 12px（手機 14px） | 內文、按鈕 |
| `--fs-3` | 14px（手機 16px） | 區塊標題 |
| `--fs-4` | 16px（手機 18px） | 頁面標題 |

現況最常用：字級 12／13／11／14／15／16 px、間距 8／6／10／4／12 px；新的 4 檔字級與 5 檔間距收斂自這些。（沒有 13px、15px 這兩檔：13 併入 12 或 14，15 併入 14 或 16，搬頁面時逐處決定。）

## 六、共用元件與守門（落實方式，擁有者看過規範後才做）

1. **共用元件**（電腦與手機同一份邏輯）：按鈕（三級＋狀態）、動作列、原位確認、狀態行（進行中／成功／失敗／空／讀不到）。第一個範例是 #2111 的設備列。
2. **搬頁面**：依頁面分張 PR，每張附搬前、搬後截圖；既有頁面全部換成共用元件，不留舊寫法。
3. **守門測試**：
   - 出現規範外的按鈕 class（`aero-btn`、`m-btn` 之外還有舊 class），測試紅；
   - 新增的 CSS 出現寫死的字級或間距（不是變數），測試紅；
   - 每個按鈕所在容器必須是規範的版型之一。
   舊頁面搬完之前，守門只對「新增、修改到的檔案」生效，免得一次全紅。
4. 規範有改動時，先改這份文件，再改程式。

## 七、擁有者的決定（2026-11-22「照建議」，四點全部定案）

1. **確定／取消的順序**：取消在左、確定在右。窄版與手機一律靠右，右邊最後一顆就是最主要的那顆，跟手機與 LINE／現代外觀的習慣一致。現況 3 處是確定在前、1 處取消在前，統一就是改那 3 處；復古外觀也照這個順序。
2. **字級與間距的檔數**：先用字級 4 檔、間距 5 檔（第五節）；現況字級約 30 種。需要更多檔，要先說理由、改這份文件。
3. **文字鈕**：保留（第二節 2-1 的三級）。
4. **搬頁面的順序**：設定頁 → 設備與帳號 → 對話區 → 其他，每張 PR 一個頁面；帳號頁（#2111）直接套用本規範，不重做。

## 八、範例：設備列與按鈕（#2111，擁有者 11-22 定案，**以下規則優先於本文其他段落**）

這是第一個照本規範做的畫面；本文的按鈕、版型、狀態行規則不得與它衝突，有衝突以這段為準。

1. 一台設備一列：左邊設備名（本機加小標「這台」），原因寫在**設備名下方一行**；右邊放鈕。
2. 鈕固定靠右、同一欄、同尺寸（電腦 92×28、手機 100×40）；窄版一律靠右。
3. 使用中：深灰底、白字、不能按，不寫原因。
4. 可切換：一般鈕，鈕上寫「切換」，不寫原因。
5. 切換中：一般鈕＋轉圈、字淡、不能按，鈕上寫「切換中…」。
6. 不能切換：虛線框、淡色、不能按，鈕上寫「不能切換」，設備名下方一句原因（例如「ASN 尚未開啟」）。
7. 黃色只給「重新登入」用：登入失效的那台那一列放黃色「重新登入」鈕（可以按），設備名下方寫「登入已失效」。
8. 不列出：沒登入這個帳號的設備、舊設備代號、已隱藏、已永久移除的設備。
9. 操作結果在原位（按的那一列下方）顯示：成功綠色一句、失敗紅色一句（說發生什麼、怎麼辦），不跳框。
10. 按鈕文字用動作說法，不用疑問句。

和本文的對應：第 3 條是「使用中（深灰）」、第 7 條是「黃色只給重新登入」、第 6 條是 4-2「不能做的事」、第 9 條是 4-3 的狀態行；一台一列版型見第三節。

## 九、這份規範沒有決定的

- 顏色（主色、危險紅、使用中深灰的色碼）：沿用現有三套外觀的變數，這份只定「什麼用途用什麼色」。
- 動畫（轉圈的寫法）：沿用現有的。
- 圖示：不在這張範圍。
