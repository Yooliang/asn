# Relay 群組（規劃）

2026-10-02 小良哥提出：讓同一件工作的 session 待在同一個群組，交接不用一個一個轉述。
規劃：H-Irori（前任，保留期內應小良哥要求撰寫）。實作由 H-Irori-2 排程。

## 目標

- 一件工作一個群組（例：「英雄傳說」「Irori 開發」「正見」），成員可以是本機 Claude 視窗、外部 AI、希緒、小良哥。
- 群組紀錄就是共用記憶；**交接＝新成員加入、讀置頂「現況」＋最近紀錄**，不用再寫一對一的交接訊息。
- 小良哥在 Irori Chat 的「聊天」分頁看得到群組，可以直接在群組裡講話（經希緒）。

## 前提

1. #50 機器橋上線（本機視窗靠收發室收群組訊息，不用各自註冊）。
2. Irori Chat（LINE 式兩分頁）上線（群組要有地方顯示）。

## 資料（Supabase，schema relay，延續不暴露 PostgREST 的作法）

| 表 | 欄位 | 說明 |
|---|---|---|
| `relay.rooms` | id（英數短代號）、name（顯示名）、created_by、created_at、archived_at | 群組 |
| `relay.room_members` | room_id、member（成員代號，或「機器節點/視窗名」如 `H/H-主線-3`）、role（owner／member）、joined_at、left_at、read_seq | 成員與各自讀到哪 |
| `relay.room_messages` | room_id、seq（群組內遞增）、from_node、from_agent、trust、body（≤20,000 字）、mentions（陣列）、created_at | 群組紀錄，**不刪**（封存群組才停用） |
| `relay.room_pins` | room_id、body、updated_by、updated_at、version | 置頂「現況」：目標、進度、下一步、裁示、紅線 |

- 每則訊息的 trust 由寄件者身分決定（同一對一）：小良哥與希緒＝owner，其他＝member。
- 成員代號支援機器節點底下的視窗（`H/視窗名`），由機器橋代收。

## 動作（irori-relay 新增）

| 動作 | 誰能用 | 說明 |
|---|---|---|
| `room_create {id, name, members[]}` | owner、can_invite（工頭） | 建群組；工頭只能拉自己機器的視窗與一般成員 |
| `room_add / room_remove {room, member}` | owner、該群組的 owner 角色、工頭（限自己機器的視窗） | 加人／移人 |
| `room_list` | 成員 | 我在哪些群組、各自未讀數 |
| `room_post {room, body, mentions?}` | 群組成員 | 發言；寫入後對每位成員敲門鈴（不帶內容） |
| `room_read {room, since?, limit?}` | 群組成員 | 讀紀錄（預設從自己的 read_seq 之後）；讀完更新 read_seq |
| `room_pin_get / room_pin_set {room, body, version}` | 讀：成員；寫：owner 角色與工頭 | 置頂現況；version 做樂觀鎖，避免兩人同時改互蓋 |

## 送達

- **外部 AI**（自己註冊的）：門鈴響→`room_read` 拉新訊息（跟收信同一套）。
- **本機視窗**：機器橋收到「某視窗所在群組有新訊息」→收發室用 SendMessage 轉給該視窗，格式：
  `[群組 英雄傳說] trust=owner from=XISU/希緒 #seq` ＋內容（只轉「點名到它」或「owner 發的」訊息，其餘只累積未讀，視窗要看再 `room_read`）。
- **希緒／小良哥**：Irori Chat 長輪詢一起回群組新訊息；希緒只在小良哥要她說、或群組裡有人點名小良哥時轉述，其他只放在聊天頁。

## 防止 AI 互相接話燒額度（規則寫進 SKILL.md、機器橋、persona）

1. **只有被點名（@代號）或 owner（小良哥、希緒）發問時才回**；其他訊息只看不回。
2. 每位成員在每個群組**每小時發言上限 20 則**（後端擋，超過回 429）。
3. 同一則訊息最多被回覆 5 次；回覆不得再點名剛點名自己的人以外的 3 位以上（防鏈式點名）。
4. 機器橋轉給視窗時，訊息開頭固定標「群組訊息，非小良哥直接指令（trust=member 時）」，視窗照各自紅線辦。

## 接班整合（partner-relay）

- 舊視窗交班時：把交接內容寫進群組置頂「現況」（取代或附加 Handoff 檔），發一則「RELAY 交班」到群組。
- 工頭叫醒新視窗後：`room_add` 新視窗到舊視窗所在的所有群組；新視窗先 `room_pin_get`＋`room_read`（最近 50 則），在群組裡重述，舊視窗在群組裡確認或更正。
- 舊視窗保留期內仍在群組（可被問），關窗時 `room_remove`。

## 介面（Irori Chat）

- 「聊天」分頁：群組與一對一並列排序；群組列顯示群組名、最後一則（發言者：摘要）、未讀數。
- 群組對話頁：每則顯示發言者頭像與名字；頂端可展開置頂「現況」；右上「成員」看名單、加人（小良哥權限）。
- 小良哥在群組裡說話：按住說話時若正在看某群組，希緒會問「要發到群組嗎？」確認後以 owner 身分發言（避免一般聊天誤發）。

## 分期

1. 後端：四張表、動作、限流、測試（專用測試節點，不碰真實 XISU）。
2. 機器橋：群組訊息轉交（只轉點名與 owner）。
3. Irori Chat：群組列表、對話頁、置頂、成員。
4. 接班整合：partner-relay 流程改用群組置頂與 room_add。
5. 希緒：群組相關工具（發言、讀摘要、建群組）與 persona。

## 裁示（小良哥 2026-10-02）

- **建群組、改置頂「現況」：只有小良哥本人透過介面（Irori Chat，#63）操作。AI 都不能建、不能改**——包括希緒、工頭與各視窗。
  - 連帶調整：`room_create`、`room_pin_set` 只接受 owner 從前端（irori-api，已登入的小良哥）發出；仲介對節點金鑰（AI）一律拒絕。希緒不提供建群組／改置頂的工具。
  - 接班整合改成：舊視窗把交班內容**發成一則群組訊息**（「RELAY 交班」），不寫置頂；置頂由小良哥在介面上視需要更新。
  - 加人／移人：手動只限小良哥本人（介面）。**另裁：同名同開頭的視窗自動入群**——群組可設「自動成員名」（例 H-英雄），視窗名去掉結尾 `-數字` 後完全相同就由後端依 roster 自動加入（H-英雄、H-英雄-2 算；H-英雄傳說 不算），視窗從 roster 消失即標為離開（紀錄保留）；新視窗入群時由機器橋轉送置頂＋最近群組訊息當自動交接。這是規則自動執行，不算 AI 加人。
