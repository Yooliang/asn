# 從頭建置 ASN

這份給想自己編譯 ASN、或連後台一起自己架的人。只想用 ASN 的話不需要看，回 [README](../README.md) 下載安裝檔即可。

分兩部分：

- **A：只編譯程式**：編出 Windows 電腦版與 Android 手機版。編出來的程式預設連 ASN 官方架好的後台。
- **B：後台也自己架**：自己開一個 Supabase 專案，套用 migration、部署 Edge Function，再讓自己編的程式連過去。

> 標有「（未實測）」的步驟，是依 repo 內的腳本、設定與 CI 推得，這份文件的撰寫者沒有在全新環境實際跑過。遇到出入請以腳本與 CI 設定為準，並歡迎回報。
> 這份文件不含任何金鑰。所有簽章金鑰、服務帳戶、後台秘密都要你自己產生，並且絕不要提交進 git。

## A、只編譯程式

### A1. 版本一覽

CI（`.github/workflows/`）實際使用的版本如下；CI 只在 Linux 上跑，Windows 與 Android 的版本以 repo 內設定與開發文件為準。

| 工具 | 版本 | 出處 |
|---|---|---|
| Node.js | 22 | CI（`asn-linux-build.yml`、`asn-backend-tests.yml`） |
| Rust | stable（需含 `cargo`、`rustup`）；Android 另加目標 `aarch64-linux-android` | CI；Android 四個目標見下 |
| Deno | 2.9.3（只有跑後台測試需要） | `asn-backend-tests.yml` |
| JDK | CI 的手機 Kotlin 檢查用 17；本機用 Android Studio 內建的 JBR 21 也可（`docs/design/ANDROID.md`） | CI／開發文件 |
| Android SDK | 平台 36（`compileSdk`／`targetSdk` 36）、`minSdk` 26、build-tools 34～36 | `src-tauri/gen/android/app/build.gradle.kts`、開發文件 |
| Android NDK | `28.2.13676358` | 開發文件 |
| Gradle／AGP／Kotlin | 由專案內的 `gradlew` 自動下載（Gradle 9.6.1、AGP 9.3.1、Kotlin 2.2.10 為開發文件所記） | 開發文件 |
| Tauri CLI | 2.12.3（`devDependencies`，隨 `npm ci` 安裝） | `relay/asn/package.json` |
| GitHub CLI（`gh`） | 內建 WezTerm 時必須 | `scripts/fetch-wezterm.mjs` |

Linux 建置要裝的系統套件列在 `.github/apt-build-packages.txt`（`libwebkit2gtk-4.1-dev`、`libgtk-3-dev`、`libayatana-appindicator3-dev` 等）。Linux 版目前以 CI 驗證為主，本文件下面的步驟以 Windows 與 Android 為重點。

### A2. 取得原始碼

```
git clone https://github.com/Yooliang/asn.git
cd asn
```

程式在 `relay/asn/`。**`npm ci` 要在 `relay/asn/` 底下跑**（repo 根目錄沒有 `package.json`）：

```
cd relay/asn
npm ci
```

### A3. Windows 電腦版

先備：

1. Node.js 22。
2. Rust：`winget install --id Rustlang.Rustup -e`，再 `rustup default stable-msvc`。
3. Visual Studio 的「C++ 建置工具」（Desktop development with C++）。
4. WebView2（Windows 11 內建；Windows 10 要另裝）。
5. 若要內建 WezTerm 終端機：安裝 [GitHub CLI](https://cli.github.com/) 並 `gh auth login`（見 A5）。

建置（在 `relay/asn/`）：

```
npm run build
```

這會依序執行：`scripts/prep.mjs`（把 Vue、DiceBear 等打包到 `ui/vendor/`，此資料夾不進 git）→ `scripts/fetch-wezterm.mjs`（取得內建的 WezTerm）→ `tauri build`，並用 `src-tauri/tauri.nosign.conf.json` 關掉更新簽章，所以**不需要任何簽章金鑰**。

成品位置：

- 安裝檔：`relay/asn/src-tauri/target/release/bundle/nsis/ASN_<版本>_x64-setup.exe`
- 免安裝的執行檔：`relay/asn/src-tauri/target/release/asn.exe`

（Linux 另會在 `bundle/deb/`、`bundle/appimage/` 出 `.deb` 與 AppImage。）

只想開發時試跑：`npm start`（等於 `tauri dev`）。

> 直接用 `cargo build` 編譯（不走 `npm run build`）時，要先在 `relay/asn/` 跑 `npm ci` 與 `node scripts/prep.mjs`，否則畫面會是沒編譯的 `{{ … }}`。

### A4. Android 手機版

先備：

1. 上面的 Node.js、Rust。
2. JDK 17 或 21（Android Studio 內建的 JBR 即可）。
3. Android SDK（平台 36、build-tools、NDK 28.2.13676358）。用 Android Studio 的 SDK Manager 安裝最方便。
4. Rust 的四個 Android 目標：
   ```
   rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
   ```
5. 環境變數 `JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME`，分別指到 JDK、SDK、NDK 資料夾。

建置除錯版 APK（只用除錯簽章，自己安裝測試用；**未實測**，指令出自 `docs/design/ANDROID.md`）：

```
cd relay/asn
npm ci
npx tauri android build --apk --debug --target aarch64
```

成品：`relay/asn/src-tauri/gen/android/app/build/outputs/apk/universal/debug/`。`src-tauri/gen/android/` 已在 git 裡，**不要**重新跑 `tauri android init`（會覆蓋 ASN 改過的檔案）。

發版用的指令（`npm run release:android`、`npm run release:play`）會用到擁有者自己的上傳金鑰與 Play 服務帳戶，自己建置不需要。若你要自己發到 Google Play，需準備自己的 Play 開發者帳戶、上傳金鑰，並改掉套件名（`tw.yooliang.asn`），這超出本文範圍（未實測）。

**推播**：手機推播要有你自己的 Firebase 專案與 `google-services.json`（放在 `relay/asn/src-tauri/gen/android/app/`，已被 `.gitignore` 擋掉，絕不提交）。沒有這個檔案照樣能編，只是 App 關著時不會響（建置腳本會印警告）。

### A5. 內建 WezTerm（Windows）

Windows 版內建一份 ASN 自己建置的 WezTerm（固定版本，記在 `relay/asn/scripts/wezterm-pins.json`），給內建終端機使用。`npm run build` 會自動呼叫 `scripts/fetch-wezterm.mjs`，它會：

1. 從本 repo 的 GitHub Release 下載該版壓縮檔（有快取就用快取）。
2. 用 `gh attestation verify` 驗證建置來源證明（所以需要 `gh` 且已登入）。
3. 核對 SHA-256 與大小，任何一項不符就讓建置失敗，不會退回上游官方版。
4. 只取其中 7 個檔放進 `src-tauri/resources/wezterm/`。

只想快速試別的、不要 WezTerm 時，可設環境變數 `ASN_SKIP_WEZTERM=1` 略過（會清空該資料夾；自己用的建置可以，但發版腳本不允許）。

### A6. 執行測試

| 範圍 | 位置 | 指令 |
|---|---|---|
| 前端與端到端 | `relay/asn` | `npm test` |
| Rust | `relay/asn` | `npm run test:rust`（CI 用 `cargo test --locked --lib`） |
| 收發室橋 | `relay/machine` | `node --test --test-force-exit --test-timeout=120000 test/*.test.mjs` |
| 雲端代理 | `relay/cloud-agent` | 同上 |
| 後台共用邏輯 | `supabase/functions` | `deno test -A _shared/` |
| 根目錄 `tests/` | repo 根 | `node tools/run-root-tests.mjs`（每支獨立程序、各自逾時；不要用 `node --test tests/*.test.mjs` 整批丟，會卡住） |

SQL 測試（`tests/` 內的 `_sql`）要真的實跑，需另外裝 pglite：`npm i --no-save --no-package-lock @electric-sql/pglite@0.5.13`（不進提交）。沒裝會略過那些測試。

已知：前端有 2 項刻意標記的「缺口」測試（標示尚未支援的功能）可能是紅的，不是你弄壞的（出自開發交接文件，版本不同時請以 CI 為準）。

### A7. 預設連到哪個後台、怎麼改

自己編譯出來的程式，預設連 ASN 官方後台：

- 後台網址：程式內預設值（`relay/asn/src-tauri/src/identity.rs` 的 `DEFAULT_URL`；收發室橋在 `relay/machine/identity.mjs`），格式是 `https://<專案代號>.supabase.co/functions/v1/relay`。
- 公開金鑰（anon key）：程式內建官方後台那一把（`identity.rs` 的 `BUILTIN_ANON`）。它是 Supabase 的公開金鑰，本來就會出現在任何前端，但**只對應官方專案**。

要連到別的後台（例如 B 部分自己架的），有兩種做法：

1. **不改程式，改環境變數**：啟動 ASN（與收發室橋、`asn-cli`）前設定 `ASN_RELAY_URL`＝你的函式網址、`ASN_RELAY_ANON_KEY`＝你專案的 anon 公開金鑰。anon key 也可以存成 ASN 資料夾裡的 `anon.key` 檔。程式會檢查金鑰所屬專案與後台網址是否一致，不一致就跳過那把金鑰。（未實測）
2. **改預設值再編譯**：把 `DEFAULT_URL`、`BUILTIN_ANON`（及 `relay/machine/identity.mjs`、`relay/machine/anon.mjs` 的同名預設）換成你自己的。改完要重跑相關測試，有些測試會檢查預設值。（未實測）

### A8. 自動更新要用你自己的簽章金鑰

官方安裝檔的自動更新，用的是擁有者的更新簽章金鑰；你自己編的版本**不能**也不該用它。

- 上面 `npm run build` 已經關掉更新簽章，編出來的版本就是沒有自動更新成品，這樣用沒有問題。
- 若你想為自己的版本做自動更新：
  1. 產生自己的金鑰：
     ```
     cd relay/asn
     npx tauri signer generate -w <你要存放的路徑>/asn.key
     ```
     它會產出私鑰檔與同名 `.pub` 公鑰檔；私鑰請妥善保管，**不要進 git**。
  2. 把公鑰內容填進 `relay/asn/src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`，並把 `plugins.updater.endpoints` 改成你自己放 `latest.json` 的網址。
  3. 發版腳本 `scripts/release.mjs` 會讀私鑰（預設在使用者家目錄 `.asn/updater/asn.key`，可用環境變數 `ASN_UPDATER_KEY_DIR` 改資料夾），把「路徑」與密碼交給 Tauri 簽章，產生 `latest.json` 與 `.sig`。
  4. 把 `latest.json`、安裝檔放到你自己的靜態網站（官方用 Firebase Hosting，見 `site/`）。

  這一整段（未實測）：repo 內的發版腳本寫死了許多官方發版流程（官網目錄、GitHub Release 轉址等），自行改用時需要調整。

## B、後台也自己架

後台是 Supabase：一個資料庫（schema `relay`）、一支 Edge Function（`relay`）、Storage、排程（pg_cron）、Realtime（當門鈴）、Auth（登入）。

### B1. 先備

- 一個 Supabase 專案（**東京或離你的使用者近的區域**；免費方案能起步）。
- Supabase CLI：`npx supabase …` 即可，先 `npx supabase login`（個人存取權杖，不進 repo）。
- 取得專案代號（project ref，Supabase 網址裡 20 個字元的那段）、資料庫密碼。

### B2. 連結專案

```
cd <repo 根目錄>
npx supabase link --project-ref <你的專案代號>
```

### B3. 套用 migration

`supabase/migrations/` 有 141 支，檔名開頭是時間戳記，**照檔名順序**套用（第一支是 `20261020000100_relay_schema.sql`，建立 schema 與資料表）。migration 已包含：

- schema `relay` 與所有資料表、函式，並對 anon／authenticated 收回權限（只給 service role）。
- 擴充 `pg_cron`（`create extension if not exists pg_cron`）與兩個排程：`relay-purge-90d`（每天清 90 天前的信）、`relay-purge-attachments`（清到期附件）。
- Storage bucket `attachments`（私有、單檔 25 MB、型別白名單）。

**本 repo 官方正式庫的做法**（見 [BACKEND.md](BACKEND.md)）：不用 `supabase db push`，而是一次只跑一支：

```
npx supabase db query --linked -f supabase/migrations/<檔名>.sql
```

官方不用 `db push`，是因為官方正式庫的 `schema_migrations` 紀錄表不完整。**全新專案沒有這個問題，理論上可以直接 `npx supabase db push`；但這一步沒有在全新專案上實測過**（未實測）。保守做法是照檔名順序，逐支用上面的指令套用，每支套完看有沒有錯誤，出錯就停下來檢查再繼續。

套用完請抽查：
- `select count(*) from relay.nodes` 能查（表存在）。
- Dashboard 的 Database → Extensions 看得到 `pg_cron` 已啟用，Storage 看得到 `attachments`。

### B4. 部署 Edge Function

```
npx supabase functions deploy relay --project-ref <你的專案代號> --no-verify-jwt
```

`relay` 自己用「節點金鑰」驗證，所以要加 `--no-verify-jwt`（`supabase/config.toml` 也有同樣設定）。官方在 Windows 上 Docker 打包失敗，所以另外加了 `--use-api`；你的環境若能用 Docker，不必加。

部署順序固定是：migration → Edge Function → 用戶端。

冒煙測試：用假金鑰與不帶金鑰各呼叫一次 `<函式網址>?action=whoami`，兩者都應回 401。

### B5. 設定值（Edge Function secrets）

用 `npx supabase secrets set NAME=…` 設定。以下**只列名稱與用途**，值一律自己產生或申請：

| 名稱 | 必要？ | 用途 |
|---|---|---|
| `SUPABASE_URL` | 必要，Supabase 自動提供 | Edge Function 連自己專案的資料庫與 Realtime |
| `SUPABASE_SERVICE_ROLE_KEY` | 必要，Supabase 自動提供 | 後台用的最高權限金鑰；只存在 Edge Function 裡，**絕不能放進任何用戶端或 git** |
| `ASN_WEB_ORIGINS` | 選用，預設關 | 網頁版的網域（逗號分隔、確切網址）。沒設就整個網頁登入分支停用 |
| `ASN_EDGE_TTS_URL`、`ASN_EDGE_TTS_SECRET` | 選用 | 「念出訊息」：轉給自己部署的語音合成服務（`cloudflare/edge-tts/`）。兩個都設才啟用，沒設該功能回 503 |
| `FCM_SERVICE_ACCOUNT` | 選用 | 手機推播：Firebase 服務帳戶的 JSON。沒設就安靜不推播，不影響寄信 |
| `IRORI_FIREBASE_DB_URL`、`IRORI_FIREBASE_SA` | 選用，舊功能 | Firebase 訊號；兩個都設才啟用。官方現在也沒有設，可以略過 |

另外，用戶端（A7）需要的是這個專案的**anon 公開金鑰**與函式網址，不是上表任何一個秘密。

### B6. 登入（Auth）

ASN 用 Supabase Auth 登入（Google、GitHub），做法與要加的 Redirect URL 清單見 [AUTH.md](AUTH.md)。自己架時要做的事：

1. 在 Supabase Dashboard → Authentication → Sign In / Providers 啟用你要的登入方式，並填入自己向 Google／GitHub 申請的 OAuth 用戶端（Client ID／Secret，絕不進 git）。
2. 在 Authentication → URL Configuration 的 Redirect URLs 加入 AUTH.md 列出的本機回呼網址等。
3. Google 的 OAuth 同意畫面需要應用程式首頁、隱私權政策與服務條款網址；這部分官方由官網提供，自己架要提供自己的。

（未實測：官方專案的 Auth 設定是在 Dashboard 手動做的，repo 沒有一鍵腳本。）

### B7. Storage

附件用私有 bucket `attachments`，由 migration `20261020000500_attachments.sql` 建立，**不用手動建**。用戶端完全碰不到這個 bucket，只有 Edge Function 用 service role 簽上傳與下載網址。到期檔案由排程標記、函式的 `attach_sweep` 經 Storage API 刪除。

### B8. Realtime（門鈴）

Edge Function 寫入訊息後，用服務金鑰呼叫 Realtime 的 broadcast，通知用戶端去拉信。新專案不需額外設定；用戶端訂閱用的是你專案的 anon 金鑰。

### B9. 選用：手機推播（FCM）

1. 建一個 Firebase 專案，並在其中註冊 Android App（套件名要與你編譯的一致）。
2. 把 `google-services.json` 放到 `relay/asn/src-tauri/gen/android/app/`（不進 git），再重新編譯 APK。
3. 建一個只供發送推播的服務帳戶，把它的 JSON 設成 Edge Function 秘密 `FCM_SERVICE_ACCOUNT`。

設計與限制見 [design/PUSH-FCM.md](design/PUSH-FCM.md)。（未實測）

### B10. 選用：官網與更新伺服器

`site/` 是純靜態的官網，用 Firebase Hosting 部署（`site/.firebaserc` 指向官方專案，要改成你自己的）。自動更新用的 `latest.json` 放在 `site/public/update/`，自己架時把 `tauri.conf.json` 的 `plugins.updater.endpoints` 指到這裡（見 A8）。官網內容（藍圖、待辦、發版紀錄）存在資料庫的 `public.asn_site_*` 表，寫法見 `site/README.md`。（未實測）

### B11. 讓自己編的程式連到自己的後台

照 A7：設好 `ASN_RELAY_URL`（`https://<你的專案代號>.supabase.co/functions/v1/relay`）與 `ASN_RELAY_ANON_KEY`（你專案的 anon 公開金鑰），或改預設值重新編譯。

第一次啟動、登入完成後，你的帳號會成為你自己這個後台的第一位使用者；之後要加電腦與夥伴，照 [ARCHITECTURE.md](ARCHITECTURE.md) 與 [AUTH.md](AUTH.md)。

### B12. 維運守則

- 正式庫只用唯讀查詢，不要在 SQL 或 log 輸出金鑰雜湊、金鑰、信件內文。
- migration 只新增檔案、不改已套用的；每支都有對應的回復做法。
- 後端單元測試：`cd supabase/functions && deno test -A _shared/`。
