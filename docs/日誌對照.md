# 日誌對照（#2104）

目的：每一版的行為由團隊看 log 自己驗，不再請擁有者到設定頁點。這份是「某個行為 → 對應哪一行 log → 什麼時候寫 → 怎麼查」的對照表。
行格式以程式為準：`relay/asn/ui/lib/state-log.mjs`（前端狀態變動行）、`relay/asn/src-tauri/src/ui_log.rs`（寫檔、輪替、遮 email、`[elog]`）。守門測試 `relay/asn/test/log-guard-2104.test.mjs` 會確認每一項都產得出對應的行、行裡沒有 token／密碼／未遮的 email，也會確認本文件列了每一種行的開頭。

## ui.log 在哪裡
- 位置：機器資料夾（跟 `bridge.log` 放一起）：Windows `%USERPROFILE%\.asn\machine-<ID>\ui.log`。設定頁「檢視記錄」開的就是它。
- 輪替：超過 1 MB，現有的 `ui.log` 改名成 `ui.log.1`（舊的 `.1` 直接覆蓋，只留一份）再開新的 `ui.log`。查的時候兩個檔都要看；改名失敗才退回只留後半。
- 每行格式：`時間 等級 內容`，例如 `2026-11-22T10:00:00.000Z info [ASN] ai-cli 變動：…`。每行最多 500 字、控制字元換成空白；一次最多收 200 行。
- email 一律遮成 `<email>`：寫檔出口（`ui_log::append`）對每一行都遮，前端 `[ASN]` 整批寫入和 `[elog]` 都一樣，所以不會有帳號 email 留在檔案裡。
- 不寫 token、密碼、信件內容。狀態行只寫版本、固定代號、資料夾路徑、白話原因；登入只寫 `in`／`in(N)`／`out`／`unknown`，不寫帳號。

## 對照表（`[ASN] ` 開頭的是前端寫的；前面都還有時間與等級）

「初始」＝這個程式執行期間第一次拿到結果時記一行；「變動」＝之後只在值變了才記，沒變不記。

| 行為 | log 行格式 | 什麼時候寫 | 驗收時怎麼查 |
|---|---|---|---|
| AI 工具版本、是否最新、登入狀態（`ai_cli_status`）初始 | `[ASN] ai-cli 初始：claude 版本=1.2.3 最新=latest 登入=in；codex 版本=0.5 最新=behind(0.6) 登入=out` | 第一次查詢成功 | `grep "ai-cli 初始" ui.log` |
| 同上，變動 | `[ASN] ai-cli 變動：claude 版本 1.2.3→1.2.4；claude 最新 latest→behind(1.3.0)；codex 登入 out→in`（工具增減寫 `X 出現`／`X 消失`） | 之後任一欄位變了 | `grep "ai-cli 變動" ui.log` |
| AI 工具是否裝好（`ai_cli_detect`）初始 | `[ASN] ai-cli-detect 初始：claude 已安裝 1.0；codex 未安裝` | 第一次偵測 | `grep "ai-cli-detect 初始" ui.log` |
| 同上，變動 | `[ASN] ai-cli-detect 變動：codex 未安裝→已安裝 0.9` | 之後有變 | `grep "ai-cli-detect 變動" ui.log` |
| Claude 外掛狀態初始 | `[ASN] 外掛 初始：installed 0.2.63`（狀態是固定代號 checking／installed／removed／no_claude／failed／update_failed；有版本或原因接在後面，原因寫成 `原因：…`） | 第一次拿到外掛狀態（啟動後安裝檢查、設定頁讀取、`claude-mod-status` 事件、引導頁檢查都走同一出口） | `grep "外掛 初始" ui.log` |
| 同上，變動 | `[ASN] 外掛 變動：checking→installed 0.2.63` | 狀態文字變了 | `grep "外掛 變動" ui.log` |
| 工作資料夾加入 | `[ASN] 資料夾 加入：<路徑>` | 成功加入（已在清單的重複項不記） | `grep "資料夾 加入" ui.log` |
| 工作資料夾移除 | `[ASN] 資料夾 移除：<路徑>` | 成功移除 | `grep "資料夾 移除" ui.log` |
| 工作資料夾被拒 | `[ASN] 資料夾 拒絕：加入 <白話原因>`／`資料夾 拒絕：移除 <白話原因>` | Rust 端驗證不過（原本只寫 stderr） | `grep "資料夾 拒絕" ui.log` |
| 後端 `elog!`（原本只寫 stderr） | `時間 info [elog] <原本 stderr 的內容>` | 每次呼叫 `elog!`（電腦版、機器資料夾設好之後；之前的呼叫只寫 stderr） | `grep "\[elog\]" ui.log` |
| 程式結束、panic | `[ASN] 程式結束：…`／`error [ASN] 程式錯誤結束（panic）：…`（既有，非本次新增） | 結束時 | `grep "程式結束\|panic" ui.log` |

## 驗收怎麼查（範例）
1. 開 `%USERPROFILE%\.asn\machine-<ID>\`，看 `ui.log`，必要時一併看 `ui.log.1`（輪替過的舊記錄）。
2. 該版要驗的行為，用上表最後一欄的 grep 找對應的行；「初始」行在啟動後不久就會出現，「變動」行要做了動作（升級工具、登入／登出、加／移資料夾）才會出現。
3. 沒看到該有的行：先看 `ui.log.1`，再看是不是 3 秒內還沒整批寫入（前端每 3 秒送一批）。
4. 看到 `<email>` 是正常的，不是壞掉；要查是哪個帳號請用別的管道，log 不留帳號。
