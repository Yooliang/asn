### 完成定義（每一條都要在真機上點過）

**開得起來**
- [ ] 內建通道：Gemini、Grok 從三頁精靈開出背景工作者，名單出現、能收信回信。
- [ ] 經 pi：各家模型開出 pi 視窗，擴充已載入、名單出現、能收信回信，模型照精靈第 3 頁所選。
- [ ] 手機和別台設備也能開「經 pi」，並帶提供者和模型。
- [ ] Linux 設備（日本VM）能開新夥伴；沒有桌面的 Linux 有說明怎麼設定；不能開的設備反灰並寫原因。
- [ ] 不能開的組合（沒裝 pi、沒登入、設備離線）反灰並寫原因，不靜默失敗。
- [ ] 「自己開的 CLI」永遠不能選；CLI 授權提示不代答（守門測試）。

**關得掉**
- [ ] 內建通道「關」分兩項：**停止這次**（程序結束，之後能再開回來）、**移除這個夥伴**（從名單和設定移除）。
- [ ] pi「關閉」：只結束目標 pi 和它的子孫程序，不碰 ASN 自己、不碰使用者的終端、不誤殺同名者。
- [ ] 電腦和手機選單都能用；關完沒有殘留程序。

**能切模型**
- [ ] 內建通道：改設定檔後重啟工作者，停 2～3 秒，對話接得上；選單寫明「會短暫重開」。廠牌有原生 set_model 的（先探測）就用原生的。
- [ ] pi：電腦和手機都能切；pi 忙的時候排隊、等這回合結束再換，不要等到逾時。
- [ ] 切完名單和詳情顯示新模型。

**能改名**
- [ ] 內建通道：改名後夥伴 ID 不變、交接檔和往來記錄接得上、重開不失憶；同名擋住。
- [ ] pi：改名後名單和收件名一致，夥伴 ID 不變。

**能接手自己開的 pi**
- [ ] 裝了擴充的 pi 開了就自動進名單（已有，回歸）。
- [ ] 沒裝擴充的 pi：「接手」後接續同一段對話，變成能收信、能切模型、能關的視窗。
- [ ] 找不到唯一對話就拒絕並寫原因，不猜；只讀對話檔第一行。

**活躍度跨設備**
- [ ] 別台設備上的夥伴，照後台的最後活動時間亮燈，不再一律閒置。
- [ ] AI 在忙但沒寄信也算活躍（至少內建通道和裝了擴充的 pi）。
- [ ] 舊版 ASN 不壞：後台沒有新欄位時退回現在的算法。

**去 Irori 化、舊後台停用**
- [ ] 程式、設定、排程、文件全部改成新名；舊名只剩相容層，照樣能用。
- [ ] 下載檔已經搬到 ASN 自己的網站，舊連結有轉址。
- [ ] 舊後台連續 7 天零流量後**暫停**（不刪，可以恢復）。
- [ ] 已知例外：安裝檔的廠商名維持 `irori`（改了會讓已安裝的人升級斷掉）。
- [ ] 不在 0.2：拿掉相容層、刪舊後台、刪舊資料夾，都在 2027-01-19 以後（見第五節）。

## 四、驗收規則（從 #407 留下來的）

1. **權限**：遠端開窗、接手、切模型都不跨出白名單資料夾（`allow_dirs`、`write_dirs`）。
2. **關乾淨**：關閉要清掉整棵程序樹；只殺 ASN 開的或已接手的程序，先確認 PID 是誰的。
3. **不失憶**：改名、重啟、切模型都以 session／夥伴 ID 為準，交接檔接得上，不會被當成新夥伴。
4. **隱私**：接手只讀對話檔第一行；不傳明文金鑰。
5. **不可回復的步驟**：先搬資料、再觀察、再暫停，每一步都要小良哥明講同意，並留恢復路徑。
