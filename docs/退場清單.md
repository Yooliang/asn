## 規則

1. 決定要用新的取代舊的那一天，就把舊的登記進這張表：誰取代它、誰負責到刪掉為止、什麼條件下刪。
2. 登記之後舊的只修不加：不新增檔案，行數不增加，守門測試會擋。
3. 修正真的需要多寫幾行時，同一張 PR 調高基準，並在下面「基準調整紀錄」寫原因；審查的人要看這一筆。
4. 新功能只做在取代它的那一邊。單上寫「兩邊都要」時，先停下來問領隊，不要照抄一份到舊的那邊。
5. 負責人要負責到舊的刪掉為止。部署、試跑、切換、觀察這類工作不適用「每項 30 分鐘」，要排進開發順序。
6. 刪掉之後，把那一列搬到「已退場」表。

## 怎麼數

從登記的路徑往下走訪所有檔案，略過 `node_modules`。不算的有三種：測試（任何一層資料夾叫 `test`、`tests`、`__tests__`，或檔名含 `.test.`、`_test.`）、Markdown（`.md`）、純文字說明（`.txt`）；理由是修正一定要附回歸測試，測試可以增加，文件也可以更新。檔數是剩下的檔案數，行數是這些檔的換行字元總數。二進位檔（內容裡有數值為 0 的位元組）算檔數、不算行數；目前登記的路徑裡沒有這種檔。

要看現在實際的數字：在 `relay/asn` 底下跑 `node --test test/retiring-ratchet.test.mjs`，輸出最後會印出每一列數到的檔數和行數。新登記一列時，基準就填這裡印出來的數字。
