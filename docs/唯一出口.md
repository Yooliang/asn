# 唯一出口

> 動手前先查這張表：要做的事表上有出口，就一定走那個出口，不准另寫一份。
> 新增一類共用出口時，同一張 PR 要登記進來；出口搬家、改名，或副本收掉了，也在同一張 PR 改這張表。
> 守門測試：`relay/asn/test/single-outlet-map.test.mjs`。它逐列檢查表上寫的檔案真的存在、同一件事沒有寫兩列（開發紀律第零節第 3、4 條）。

## 怎麼讀、怎麼維護

- 欄位固定五欄，名稱與順序不能改；整份文件只能有這一張五欄的表。
- 「唯一出口」「守門測試」「還沒收斂的副本」三欄裡，檔案路徑一律用反引號包起來，寫從 repo 根目錄起算的完整相對路徑，守門測試會逐一檢查檔案或資料夾存在。這三欄的反引號只准包路徑或函式名（函式名只用英數與底線）；其他要用反引號的說明寫在「怎麼用」那一欄。
- 「守門測試」：寫的是會擋住「繞過出口」或「出口壞掉」的測試。沒有就寫「無（靠人）」，不要編造；只測行為、沒有擋繞過的，要在後面註明。
- 「還沒收斂的副本」：確實只有一份就寫「無」；還有別份實作就列出路徑。這一欄只准變少：副本刪掉了，就把它從這一欄拿掉。
- 修毛病時，這一欄列的副本都要一起看、一起改（開發紀律第一節第 4 條）。
- 表上找不到要做的事：先用關鍵字搜程式，確定沒有既有做法再寫；寫出來的東西如果會被兩個以上的地方共用，就登記成新的一列。
- 很多副本在 `relay/machine`（Node 版機器橋）和 `relay/cloud-agent`（雲端代理的舊腳本）。這兩個資料夾正在退場，只修不加，新功能做在取代它們的那一邊，見 [退場清單](退場清單.md)。
