# App 關著手機也要響（FCM 推播，#797）：設計草稿

> 公開版草稿（asn調查員，2026-11-07）。審過後放 `docs/design/PUSH-FCM.md`。憑證、威脅模型、權杖保護放在私有文件，不在這裡。
> 版號暫定 **0.2.11**（0.2.10 是「從別台打字」；不論打字和 Linux 版號怎麼排，推播都在兩者之後）。

## 現況（main ea420654 之後）

- 手機收信靠兩條：
  1. **門鈴**：App 開著時連 Supabase Realtime 的 `realtime:<bell_topic>`，後台 `ring()` 敲一下，App 就去拉信（`relay/asn/src-tauri/src/bell.rs`、`supabase/functions/relay/index.ts` 的 `ring`）。門鈴不帶內容。
  2. **前景輪詢**：收信 2 分鐘、名單 1 分鐘（`docs/design/ANDROID.md`）。
- Android 原生端沒有前景服務、沒有系統通知、沒有通知權限；來信只有 App 內頂端橫幅。
- 寄給本人的信：手機 30 天內開過就另外留一列（#796），打開 App 看得到，但**App 關著時完全不會響**（CHANGELOG 已列為已知問題）。
- Firebase 專案 `asnmessenger` 已存在（官網 Hosting、Play 發版），FCM 相關 API 已啟用，還沒有註冊 Android App。

## 目標與不做的事

- 目標：手機 App 關著（或在背景被系統凍結）時，有人寄信給本人或本人名下夥伴需要本人注意時，手機跳一則系統通知；點下去打開 App，App 照舊去拉信。
- **推播只帶固定文字**（例如「ASN 有新訊息」），不帶寄件人、內文、群組名、未讀數。內容一律打開 App 才從後台拉。
- 不做背景靜默拉信；不做通知上的快速回覆；不做 iOS。
- 電腦版不變。

## 流程

1. 手機登入後取得 FCM 權杖，用節點金鑰呼叫 `push_register` 交給後台。
2. 寄給本人的信、或夥伴在等你回覆時，Edge 寄出之後再問後台「要推哪幾台」：推給**收件的那個人**名下、現在不在線（沿用 3 分鐘在線判斷；設成「顯示為離線」的人沒有在線紀錄，也算不在線）、30 天內開過 App（看推播權杖多久前重報過，App 每次啟動都會重報）的手機，同一台 60 秒最多一則；收件人由後台寄信的結果決定，不採用戶端給的值。Edge 再呼叫 FCM 送固定文字。
3. 手機收到系統通知；點下去打開 App → 門鈴／拉信照舊。
4. 登出、換帳號、移除裝置：App 呼叫 `push_unregister`；連不上時由後台的清除規則補上。

## 要改的地方

| 層 | 改什麼 |
|---|---|
| 資料表 | 新表記「哪台手機節點的推播權杖」（每台一個、全表唯一）；註冊、取消、清除過期的函式；寄信時回傳「要推的手機節點」 |
| Edge（relay） | `push_register`／`push_unregister` 兩個動作；寄信類動作拿到「要推的節點」後呼叫 FCM HTTP v1；FCM 回權杖失效就刪 |
| Android | Firebase Messaging 相依與 google-services 外掛；`FirebaseMessagingService`（收權杖更新、收通知）；通知頻道；Android 13+ 的通知權限詢問；權杖交給 Rust／前端再送後台 |
| 前端（手機畫面） | 設定頁「App 關著時也通知我」開關與權限說明；權限被拒時的提示 |
| 文件 | `ANDROID.md` 第二期、CHANGELOG、Play 資料安全表單說明 |

## 需要小良哥準備的

1. 在 `asnmessenger` 註冊 Android App（`tw.yooliang.asn`）。`google-services.json` 不進 repo，比照簽章檔放在建置機的本機位置，由建置流程讀取。
2. 建一個只給發推播用的服務帳戶，金鑰由本人設進後台秘密。
3. Play Console 的資料安全表單更新（會多「裝置識別碼用於通知」）。
4. 實機：至少一台常用的國產手機（背景限制較嚴）一起測。

## 分成幾個 PR、每個怎麼驗

| # | 內容 | 驗法 |
|---|---|---|
| ① | 資料表＋函式（只 SQL） | pglite：註冊／換新／取消；同一個權杖換節點時舊的被刪；不在線才回傳要推；60 秒一則；節點停用就不推；權限只給後台 |
| ② | Edge：兩個動作＋送 FCM（FCM 呼叫可注入，測試不真的打 Google） | deno：參數檢查；送出的內容逐字等於固定文字（信裡放任何內容都一樣）；權杖失效會刪；log 不出現權杖；沒有設秘密時安靜不送；契約清單 |
| ③ | Android：Firebase 相依、服務、通知頻道、權限、權杖上報 | 建置（play／sideload 兩個管道）；實機：App 關著時寄信會響、點通知打開 App 拉到信、60 秒內連寄只響一則、登出後不響 |
| ④ | 設定頁開關、文案、文件、CHANGELOG | 前端測試；實機走一次設定頁；Play 表單 |

- 上線順序照慣例：① 的 migration 先上並確認 → ② 部署 relay → ③④ 進候選版。
- ② 上了但手機還沒更新時：沒有任何手機註冊權杖，後台不會送，對現有使用者沒有影響。
