# App 關著手機也要響（FCM 推播，#797）：設計草稿

> 公開版草稿（asn調查員，2026-11-07）。審過後放 `docs/design/PUSH-FCM.md`。憑證、威脅模型、權杖保護放在私有文件，不在這裡。
> 版號暫定 **0.2.12**（11-09 重排：0.2.10 是看別台終端的修正、0.2.11 是 Linux；推播排在兩者之後）。

## 現況（main ea420654 之後）

- 手機收信靠兩條：
  1. **門鈴**：App 開著時連 Supabase Realtime 的 `realtime:<bell_topic>`，後台 `ring()` 敲一下，App 就去拉信（`relay/asn/src-tauri/src/bell.rs`、`supabase/functions/relay/index.ts` 的 `ring`）。門鈴不帶內容。
  2. **前景輪詢**：收信 2 分鐘、名單 1 分鐘（`docs/design/ANDROID.md`）。
- Android 原生端沒有前景服務、沒有系統通知、沒有通知權限；來信只有 App 內頂端橫幅。
- 寄給本人的信：手機 30 天內開過就另外留一列（#796），打開 App 看得到，但**App 關著時完全不會響**（CHANGELOG 已列為已知問題）。
- Firebase 專案 `asnmessenger` 已存在（官網 Hosting、Play 發版），FCM 相關 API 已啟用，還沒有註冊 Android App。

## 目標與不做的事

- 目標：手機 App 關著（或在背景被系統凍結）時，有人寄信給本人或本人名下夥伴需要本人注意時，手機跳一則系統通知；點下去打開 App，App 照舊去拉信。
- **推播只帶固定文字**（例如「ASN 有新訊息」），不帶寄件人、內文、群組名、未讀數。內容一律打開 App 才從後台拉。
- 不做背景靜默拉信；不做通知上的快速回覆；不做 iOS。
- 電腦版不變。

## 流程

1. 手機登入後取得 FCM 權杖，用節點金鑰呼叫 `push_register` 交給後台。
2. 寄給本人的信、或夥伴在等你回覆時，Edge 寄出之後再問後台「要推哪幾台」：推給**收件的那個人**名下、現在不在線（沿用 3 分鐘在線判斷；設成「顯示為離線」的人沒有在線紀錄，也算不在線）、30 天內開過 App（看推播權杖多久前重報過，App 每次啟動都會重報）的手機，同一台 60 秒最多一則；收件人由後台寄信的結果決定，不採用戶端給的值。Edge 再呼叫 FCM 送固定文字。
3. 手機收到系統通知；點下去打開 App → 門鈴／拉信照舊。
4. 登出、換帳號、移除裝置：App 呼叫 `push_unregister`；連不上時由後台的清除規則補上。

## 要改的地方

| 層 | 改什麼 |

## Play 資料安全表單要寫的內容（草稿，送審前請以 Google 當時的 Play 說明與 Firebase 隱私說明頁核對）

**資料類型：裝置或其他 ID（FCM 推播權杖）**
| 項目 | 填法 | 說明 |
|---|---|---|
| 是否收集 | 是 | 推播權杖（含 Firebase 安裝識別碼）；後台存權杖並與這支手機的節點綁在一起 |
| 是否分享 | 否 | Google／Firebase 是代為處理資料的服務供應商（只負責把通知送到這支手機），依 Play 對「分享」的定義不算分享；送審前再對照 Play 當時的定義 |
| 用途 | 應用程式功能 | 只用來送「ASN 有新訊息」的提醒；不用於廣告、行銷、分析 |
| 是否選用 | 是（選用） | 設定頁可關「App 關著時也通知我」，系統通知權限也可以拒絕；不開推播不影響其他功能 |
| 是否暫時處理 | 否 | 權杖會存在後台，直到刪除 |
| 傳輸加密 | 是 | HTTPS／TLS |
| 使用者可要求刪除 | 是 | 關掉推播或登出就刪（另外 Firebase 端的權杖也一併刪）；沒刪成時 60 天沒更新自動清；整個帳號的刪除照現有流程（來信要求） |

- **不申報「訊息」類資料**：信件內容不經過推播服務，通知只有固定文字「ASN 有新訊息」，不帶寄件人、內文、群組名、未讀數。
- 不收集：位置、聯絡人、檔案、通話內容。（推播以外 App 本身的資料項目，如帳號、訊息、照片檔案，照既有的表單內容，不在這一節。）
- 若 Firebase 現行說明另列了診斷、安裝識別碼等其他資料類型，以 Google 當時的說明為準補進表單（本草稿未查證最新版，送審前必核對）。

**權限宣告**
- 我們自己宣告：`INTERNET`、`VIBRATE`、`RECORD_AUDIO`（通話，既有）、`POST_NOTIFICATIONS`（新，Android 13 以上，第一次才問、只問一次）；自行安裝版另有 `REQUEST_INSTALL_PACKAGES`（既有）。
- Firebase 套件合併進來的：`ACCESS_NETWORK_STATE`、`WAKE_LOCK`、`com.google.android.c2dm.permission.RECEIVE`（也可能還有以套件名稱命名的 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`，那是內部用、非敏感）。這是以 firebase-messaging 一般會合併的為準；**待有 `google-services.json` 能建置之後，核對 merged manifest（`app/build/intermediates/merged_manifests/`）實際有哪些再改**。都屬一般權限，不需另外的敏感權限宣告。

## 順序

- 這份設計先合。PR① 可以先寫，等 Firebase 那邊準備好才上線；PR② 送 FCM 的部分要等服務帳戶設進後台秘密才能真的驗。

- 手機從 0.2.1（#652）起就會在在線回報裡帶平台 `android`，註冊推播時後台用它判斷是不是手機；PR③ 要在第一次在線回報成功之後才註冊權杖。
