# 登入失效通知（0.1.113 設計）

起因：10-30 晚上工作機 Claude 登入失效（畫面「Login expired · Please run /login」），asn真、雯 的視窗全停，轉交一直逾時；小良哥在手機上找不到「切換帳號」那頁，也沒有人通知他是登入壞了。

目標：某台電腦的 Claude 登入失效時，**本人手機收到一則通知**，點一下就到那台電腦的「設備與帳號」頁；**切換一定由本人按**，AI 不能代按。

不做：不自動切換帳號、不自動 `/login`、不從別台 SSH 進去修、**不重開任何程序**（asn真 10-31 定案）；登入壞了但所有視窗都閒著時不會被發現（第一節只看有在跑的視窗，可接受）。

版本與基點（asn真 10-31 定案）：排 0.1.113，不進 0.1.112；實作以 main 為基點，併入下面第六節的三項。

## 一、偵測（在發生問題的那台電腦上，由收發室的橋接程式做）

橋接程式（asn-bridge，Rust）和 Claude 是不同程序，Claude 登入壞了它還活著（10-30 w02 的收發室還能寄出「轉交逾時」通知就是證據）。

訊號來源：Claude 的對話紀錄 `~/.claude/projects/**/*.jsonl`。登入錯誤會寫成一筆合成的助理回覆，有結構化欄位，不必比對文字：

```
{"type":"assistant","isApiErrorMessage":true,"error":"authentication_failed",
 "message":{"model":"<synthetic>","content":[{"type":"text","text":"Login expired · Please run /login"}]}, ...}
```

本機所有紀錄裡實際出現過的錯誤種類：`authentication_failed`（登入過期）、`oauth_org_not_allowed`（組織停用訂閱）、`rate_limit`、`server_error`。

- **算登入失效的**：`authentication_failed`、`oauth_org_not_allowed`。
- **不算的**：`rate_limit`（額度用完，另一回事）、`server_error`（暫時性）。
- 讀法沿用 `usage.rs` 的增量讀取（已經在掃同一批檔案、有位移快取），多認一種行：`isApiErrorMessage==true` 且 `error` 是上面兩種之一。
- **判定**：10 分鐘內有 2 筆以上（同一視窗或不同視窗都算），而且這段期間沒有任何一筆真的模型回覆（`model` 不是 `<synthetic>`、有 usage）。只看最近 30 分鐘內新增的行，開機時不翻舊帳。
- **恢復**：之後看到任何一筆真的模型回覆，就算恢復，下次失效可以再通知一次。
- 失效期間只通知一次。另外每 6 小時最多再提醒一次，免得一直響。

轉交逾時不能單獨拿來判定（對方忙、關機也會逾時），只在通知內文附上「這段時間轉交逾時 N 次」當佐證。

## 二、通知（寄給本人）

橋接程式用收發室的身分寄一封信給**這台電腦的擁有者本人**（`u:<擁有者 id>`；寄件人顯示「收發室通知」）：

> 工作機的 Claude 登入失效（最後一次錯誤 21:35，帳號 xxx@…）。這段時間轉交逾時 3 次。
> 【開啟工作機的設備與帳號】

- 那顆按鈕只是**開頁面**：手機打開「設備與帳號」，直接停在那台電腦的細部（現有 `openAcct({node})`）。按鈕本身不帶任何切換權限。
- 同時在帳號回報多帶 `login_failed: true`，手機帳號頁那台那個帳號標紅「登入失效」。**不只改 `account_switch.ts`**：帳號回報進資料庫是逐欄重組的，不認得的欄位會被丟掉，所以要一個**新 migration**，和 0.1.113 的 `login_incomplete` 後台欄位**合成同一個 migration、同一張實作**：
  - 兩條寫入：`asn_relay_acct_roster_report`、`asn_relay_acct_quota`（另有舊的 `asn_relay_acct_report` → `relay.asn_accounts` 那條，一併確認）都要收 `login_failed`、`login_incomplete`。
  - 一條讀出：`asn_relay_acct_roster` 回傳這兩個欄位。
  - Edge 白名單（`account_switch.ts`）收這兩個欄位；手機讀取端（`mobile-acct.mjs`）顯示。
  - 舊版用戶端不帶這兩個欄位時行為不變（預設 false），migration 只加欄位、可回復。
- 系統層推播：目前後台沒有手機系統推播，只有門鈴（App 開著或背景訊號）。第一期靠「本人信」＋門鈴；手機鎖屏通知另外排，不擋這次，另開一張。

寫入實作時的三條規定（asn真 審 #579 補的）：
1. 讀對話紀錄只取 `type`／`isApiErrorMessage`／`error`／`model`／時間戳；內容與 `text` 一律不讀進記憶體以外、不進通知、不進 log。
2. 通知內文只放：電腦名、最後錯誤時間、目前帳號 email、轉交逾時次數；不帶錯誤原文。
3. 與「切換後監看登入檔」共用**同一個回報管道**（實際帳號 email＋`login_failed`），不做兩套寄給本人的路徑。

要確認的一點：橋接程式寄 `u:<id>` 的路徑。AI 視窗現在就能寄 `u:<id>`，橋接程式的系統信目前只會回原寄件人，要加一條「寄給擁有者」的路徑，擁有者 id 由後台依節點查，不寫死。

## 三、切換（本人按）

完全沿用現有遠端切換，不新增權限：

1. 本人在手機那頁選要換的帳號 → 手機用本人登入憑證簽章呼叫 `acct_switch`（後台 `owner_sign.ts` 驗）。
2. 目標電腦取到指令。`trust_signed` 預設開，本人簽章的指令不用那台有人按「同意」——工作機沒人在也能換。限流照舊每小時 3 次。
3. #577 的檢查擋掉「登入不完整」的帳號（10-30 21:35 就是切到這種帳號才整台壞掉）。

AI 為什麼按不了：簽章只能由本人登入的手機或電腦畫面產生；AI 節點呼叫 `acct_switch` 沒有本人簽章，後台回 forbidden；`asn-cli` 也不提供這個指令。這次加一條守門測試：沒有本人簽章的 `acct_switch` 必須被拒（拿掉檢查要會紅）。

## 四、要動的地方與工時

| 位置 | 內容 |
|---|---|
| `src-tauri/src/usage.rs` 或新檔 `login_watch.rs` | 認錯誤行、判定、恢復、去重 |
| 橋接程式系統信 | 寄給擁有者本人、附開頁按鈕 |
| 新 migration（和 `login_incomplete` 後台欄位合併） | 兩條寫入、一條讀出、舊版預設值；pglite 測試 |

約 2～3 天（含 migration 與第六節兩項）。前提 #576（手機設備與帳號返回鍵防呆）已合進 main（4a2a01fd）。

## 六、併入這張實作的另外兩項（asn真 10-31 定案，0.1.113）

原本「切換後三項」改成下面三項，併成這張的實作，以 main 為基點，**不做重開任何程序**：

1. **外部改寫登入檔時回報實際帳號**：切換之後，若有別的程式把 `~/.claude` 的登入檔改回舊帳號，橋接程式只**回報目前實際的帳號 email**（走第二節同一個回報管道），不重開、不關任何程序。
2. **回存只留「切走時」，並先核對權杖帳號**（小良哥 #1738、asn真 #1740）：
   - 刪掉現在每分鐘把目前登入抄回帳號庫的那一步。它原本是怕續期憑證輪替後庫裡的副本變舊，但「切換時」本來就會先回存一次（那一刻的就是最新的），每分鐘這份多餘；而且別的程式（10-30 是工作機上的 Orca）換掉登入檔時，它會把別人的權杖抄進錯的帳號名下、弄壞好的副本。
   - 保留「切走時回存」；回存前核對權杖確實屬於 `.claude.json` 裡那個帳號，對不上就**不存**，並回報（走第二節同一個回報管道）。
   - 帳號清單的回報照舊（那是讀，不寫庫）。
3. **登入失效通知**：本文第一到五節。

三項共用同一個回報管道與同一個 migration。第 1、2 項的細節（比對的欄位、拒絕時的錯誤碼）寫實作時再補進這份文件。
