# 密碼與機密保管（#26）

目標：密碼要怎麼安全地經過 ASN 交給 AI 用的程式，最好連 AI 也看不到。

## 原則

密碼只交給「要密碼的那個程式」，**永遠不進**：模型、信件、往來記錄、log、檔案、指令列參數、環境變數、剪貼簿。

有兩個前提要先講清楚：

1. 「AI 看不到」和「AI 不能使用」是兩件事。只要 AI 能叫一個程式去做需要密碼的事，AI 就等於能「請求使用」密碼。所以每一層都把重點放在：**使用者每次親眼看到是誰、要做什麼、再決定**，而不是假裝 AI 完全無法影響結果。
2. 沒有任何一層能擋住「已經在你電腦上、以你的身分執行的惡意程式」。下面每一層都誠實寫出這一點。

## 四個層級與分期

| 層級 | 做什麼 | 狀態 |
|---|---|---|
| 1. 本機一次性傳遞 | ASN 小幫手 `asn-askpass`（GIT_ASKPASS／SSH_ASKPASS）→ 本機管道 → ASN 跳窗 → 密碼直接回給 git／ssh | **第一期，已實作** |
| 2. 遠端傳遞 | 別台／雲端的程式要密碼：一次性鑰匙對加密，收發室只轉密文 | **第二期，已實作**（設計與威脅模型見 [SECRET-REMOTE.md](SECRET-REMOTE.md)；下面「層級 2」一節是原始構想，以 SECRET-REMOTE.md 為準） |
| 3. 保管箱服務 | 密碼存在另一個 Windows 帳號執行的服務，AI 只拿到「代號」 | 只有設計（推薦的最終目標） |
| 4. 能不用密碼就不用 | ssh 金鑰（私鑰放保管箱或 ssh-agent）、git 認證管理員、短效權杖 | 只有設計與建議 |

「ASN 確認視窗」是四層共用的零件，也是 #23（權限詢問）要共用的視窗。第一期的實作已經把它做成可注入的介面（見「確認窗的共用介面」）。

## 層級 1：本機一次性傳遞（第一期）

### 流程

```
git／ssh ──呼叫──▶ asn-askpass.exe "Password for 'https://…': "
                       │ 1. 連本機管道 \\.\pipe\asn-askpass-<使用者代碼>（沒有 ASN 在聽＝直接失敗）
                       │ 2. 確認對面行程的執行檔就是「自己旁邊的 asn.exe」，不是才中止、什麼都不送
                       │ 3. 送一行請求：提示文字、自己的工作資料夾
                       ▼
                  ASN（正在執行的那個）
                       │ 4. 系統查出對面行程 → 往上三層的程式名稱（例：git-remote-https.exe ← git.exe ← bash.exe）
                       │ 5. 排隊（同時只有一扇確認窗）→ 跳出確認窗：程式、工作資料夾、提示、輸入欄、倒數
                       │ 6. 使用者輸入按「確定」，或按「取消」／關窗／逾時（2 分鐘）
                       ▼
                  密碼經同一條管道直接回給小幫手 ──▶ 小幫手印到標準輸出 ──▶ git／ssh 讀走
```

- **ASN 沒開**：小幫手連不上管道，結束碼 1、中文錯誤訊息到標準錯誤，標準輸出是空的。**它沒有任何自己收密碼的程式碼**（不讀標準輸入、不開視窗），守門測試掃描這一點。
- **設定**：設定頁「視窗」分類有一段「密碼小幫手」，顯示一行說明與 `setx GIT_ASKPASS "<完整路徑>"`，按鈕「複製路徑」。**ASN 不會自動改使用者的環境變數或 git 設定**，使用者自己決定要不要設。ssh 要設 `SSH_ASKPASS` 與 `SSH_ASKPASS_REQUIRE=force`（沒有終端機時 ssh 才會呼叫）。
- **執行檔位置**：和 `asn-cli.exe` 一樣放在 ASN 安裝資料夾，Tauri 打包會把 `[[bin]]` 一起放進安裝檔；安裝程式更新時比照 `asn-cli`，先把正被呼叫的檔案改名讓路。

### 管道上的訊息

一條連線一個請求，單位是「一行 JSON」：

- 小幫手 → ASN：`{"v":1,"op":"secret","prompt":"…","cwd":"…"}`（最長 8 KiB）。
- ASN → 小幫手：標頭 `{"ok":true,"len":N}` 一行，緊接 N 個位元組的密碼（UTF-8，**不在 JSON 裡**，上限 4 KiB）；失敗是 `{"ok":false,"reason":"cancelled|timeout|busy|bad_request|unsupported"}`。

密碼不放進 JSON 的原因：程式不必讓密碼經過任何 JSON 值或格式化字串，也比較容易在用完後立刻清掉。

### 確認窗的行為

- 全中文。顯示三件事：**哪個程式**（由 ASN 用系統查到的對面行程算出，不是小幫手自己報的）、**工作資料夾**（小幫手自報，只當參考）、**提示文字**（git／ssh 給的）。顯示前一律清理：控制字元換空白、拿掉雙向文字控制碼、壓縮空白、超長截斷，避免用換行或字元方向把畫面偽裝成別的內容。
- 輸入欄是密碼欄（`type=password`、`autocomplete=off`）。按確定、按 Enter 是送出；按取消、Esc、關窗是取消。
- **逾時**：確認窗開著 2 分鐘沒人理就自動取消，視窗跟著關；畫面上有倒數。
- **排隊**：同時只跳一扇。後面的請求在 ASN 這邊排隊（上限 8 個，超過回「忙碌」）；排隊期間對方放棄（例如 git 被 Ctrl+C）就直接移出，不會跳出沒人在等的窗；確認窗開著時對方斷線，視窗跟著關。
- **確認窗關閉後立刻清掉記憶體中的字串（盡力而為）**：Rust 端的密碼放在會在釋放時清零的容器，傳完就丟；管道另一端的小幫手同樣用會清零的緩衝。**做不到的部分**：網頁引擎（WebView2）輸入欄與行程間通訊自己持有的暫存、標準輸出的系統緩衝、作業系統換頁檔，都不是我們能清的。

### 確認窗的共用介面（預留給 #23）

`askpass/server.rs` 把「跳窗問使用者」抽成 `Confirmer` 介面：

- 請求（`ConfirmRequest`）有 `kind`：`Secret`（輸入一段機密，第一期唯一用到的）與 `Permission`（只問允許／拒絕，沒有輸入欄，**預留給 #23**）。
- 結果（`Verdict`）有 `Secret`、`Allow`、`Deny`、`Cancelled`、`TimedOut`。
- 排隊、逾時、對方斷線時關窗，都在 `Broker` 做，與視窗長什麼樣無關；正式版的視窗（`askpass/dialog.rs` + `ui/askpass.html`）和測試用的假視窗都實作同一個介面。畫面的純邏輯（`ui/lib/askpass-dialog.mjs`）已經認得 `permission` 種類（按鈕「允許」「拒絕」）。
- 第一期的管道**不接受** `Permission`：請求端只能要密碼。#23 要用時，在 `Broker` 另開入口即可，不必改視窗與排隊。

### 威脅模型

| 威脅 | 第一期的防護 | 殘餘風險（誠實寫出） |
|---|---|---|
| AI／模型讀到密碼 | 密碼只走「確認窗 → 管道 → 小幫手標準輸出 → git／ssh」。不進指令列、環境變數、檔案、log、信件、剪貼簿；守門測試掃描原始碼與行為 | 呼叫小幫手的是 git／ssh；如果 AI 叫一個程式把標準輸出轉存下來（例如自己寫 `GIT_ASKPASS` 包裝腳本把輸出記下來），它就拿得到。小幫手能擋的只有「路徑上不經過 AI 的東西」 |
| 同一個 Windows 使用者的惡意程式攔截 | 管道的存取控制只允許目前使用者，別的使用者連不上；拒絕遠端連線；ASN 建管道要求「第一個執行個體」（名字被別人先佔走就建失敗，不會去聽別人先建好的管道）；小幫手送出任何內容之前先驗對面是自己旁邊的 `asn.exe`（防假伺服器）；小幫手開管道時帶 SECURITY_IDENTIFICATION（伺服器不能冒用它的身分） | **同一個使用者底下，惡意程式理論上可以攔截**：它能讀 git／ssh 子行程的標準輸出、能對 ASN 做記憶體讀取或注入、能在 ASN 啟動前搶先佔走管道名字（此時 ASN 建不起來、小幫手驗不過身分，結果是「失敗而不是洩漏」，但使用者會被擋住）。這一層無法解決，要靠層級 3（另一個帳號） |
| 惡意程式冒用小幫手向 ASN 騙密碼（假提示） | 確認窗的「程式」欄由系統查到的對面行程決定，不是對方自報；提示文字經清理；每次都要使用者親自輸入 | 使用者看到的程式名稱若是 `bash.exe` 這類通用外殼，無法分辨是誰。最後一道防線仍是人 |
| 別的 Windows 使用者連管道 | 存取控制只有一筆：目前使用者的 SID（`D:P(A;;GA;;;<SID>)`，不繼承）；管道名稱含該使用者代碼 | 測試無法換成第二個 Windows 帳號去連線（沒有第二個帳號），只驗證存取控制本身的設定：受保護、恰一筆允許項、對象是目前使用者、沒有 Everyone 等；實際擋人由作業系統負責 |
| 密碼留在記憶體 | 用完立刻清零（盡力而為） | 見上：網頁引擎、系統緩衝、換頁檔我們清不到 |
| 確認窗被晾著或洪水式請求 | 2 分鐘逾時、排隊上限 8、對方放棄就撤銷、請求大小上限 | 惡意程式可以一直送請求騷擾使用者（會被「忙碌」擋住，但仍會跳窗）；之後可加頻率限制 |
| 小幫手被卡住 | 15 分鐘後自行結束 | — |
| 螢幕錄影、鍵盤側錄 | 無 | 超出範圍 |

### 守門測試（都做過「還原驗證」：故意違反規定，測試會變紅）

- 密碼不進 log／格式化輸出：掃描 `askpass/` 原始碼，輸出文字的巨集那一行不得提到密碼相關變數；持有密碼的型別不能自動衍生除錯輸出，手寫的除錯輸出只印「已隱藏」。
- 密碼不寫檔、不進環境變數、不進指令列、不進剪貼簿：掃描禁用的寫檔、設環境變數、起子程序、剪貼簿字樣；只讀兩個不是機密的環境變數；測試用的管道名稱覆寫只在除錯版。
- ASN 沒開時小幫手不自己收密碼：原始碼掃描（沒有讀標準輸入、沒有視窗或主控台輸入的程式碼，連不上的分支只回結束碼）＋ 真的把執行檔跑起來（標準輸入餵一個假密碼，標準輸出必須是空的、結束碼非 0、工作資料夾沒有留下檔案）。
- 管道安全設定：存取控制只有目前使用者一筆；同名管道被先佔走時 ASN 建不起來；小幫手送出請求之前一定先驗證對面行程（對面不是 ASN 時，伺服器端確認窗一次都沒被叫到）。
- 以上測試都只用假密碼字串、測試自己建立的管道（名稱前綴 `asn-askpass-test-`）、假確認窗與暫存資料夾，不開真的視窗、不連真的 ASN。

### 已知限制與之後可做

- 目前只支援 Windows（其他系統小幫手會回「尚未支援」）。
- ssh 的「是／否」確認與純顯示訊息（`SSH_ASKPASS_PROMPT=confirm|none`）不處理，直接回失敗並請使用者在終端機回答。
- 沒有頻率限制與「記住這個程式」的白名單（白名單屬於層級 3 與 #23）。
- 確認窗為一般視窗，沒有「安全桌面」隔離（Windows 的 UAC 那種）；那需要系統服務，屬層級 3。

## 層級 2：遠端（別台／雲端）— 只有設計

情境：雲端代理或另一台電腦上的程式需要密碼，使用者在自己的 ASN 前面。

1. 請求端（那台的程式）產生**一次性鑰匙對**，把「請求編號＋公鑰＋要什麼＋提示文字」透過收發室送給使用者的 ASN。這封信只含請求與公鑰，**不含任何機密**。
2. 使用者的 ASN 跳出同一個確認窗，顯示是哪台設備、哪個程式、要什麼。使用者輸入密碼並按確定。
3. ASN 用該公鑰加密（密封盒，每次臨時金鑰）後，以「綁定請求編號」的回信送回。**收發室只轉密文**，伺服器、信件內文、往來記錄裡都只有密文；信件內文本身不放（走信件的加密附件欄位，不進一般訊息列表、不進記錄）。
4. 請求端用私鑰解開，直接交給要密碼的程式，然後立刻銷毀私鑰與明文。
5. 限制：**綁請求編號**（回信的編號對不上就丟）、**幾分鐘內有效**（過期私鑰自動銷毀）、**一次性**（解開一次後該請求作廢）、確認窗要寫出對方設備的名稱。
6. 威脅：收發室後台被攻破只能看到密文與公鑰；請求端那台若被入侵，等同層級 1 的同使用者問題；中間人若能換掉公鑰（請求信被改），ASN 要把公鑰指紋的前幾碼顯示在確認窗，請使用者與請求端核對（高風險情境才需要）。

## 層級 3：保管箱服務（推薦目標）— 只有設計

- 密碼存在一個**以另一個 Windows 帳號執行的服務**裡，用 DPAPI 綁該帳號：AI 所在的帳號讀不到檔案、也讀不到服務的記憶體。
- AI 只拿到**代號**（例如 `github-push`），請求「用代號執行」→ ASN 跳出確認窗，寫明「要用 github-push 做什麼（哪個指令、哪個資料夾）」→ 使用者按允許（可選 Windows Hello 驗證）→ 服務自己把密碼交給 git／ssh／sudo，AI 這邊從頭到尾沒有碰過明文。
- 與層級 1 共用確認窗：`Permission` 種類（只問允許／拒絕，並可勾「這個程式、這個資料夾，30 分鐘內不用再問」這類有期限的白名單）。
- **誠實限制**：AI 仍可「請求使用」，所以**每次使用要經你確認，或設白名單**；AI 拿不到原文、帶不走，但在白名單期間它能讓服務替它做事。白名單要保守（有期限、綁程式與資料夾、可隨時撤銷）。
- 要做的工作：服務安裝（需要系統管理員權限一次）、另一帳號的建立與權限、管道存取控制改成「只允許 ASN 與 AI 所在帳號呼叫、不允許讀取」、DPAPI 儲存與備份／遺失處理、Windows Hello 串接。

## 層級 4：能不用密碼就不用 — 建議

- git 用認證管理員（Git Credential Manager）或短效權杖，不用長期密碼。
- ssh 用金鑰；私鑰放進層級 3 的保管箱或 ssh-agent（有確認的那種），不放在 AI 能讀的家目錄。
- 對外 API 優先用範圍最小、會過期的權杖。
- ASN 的角色：在設定裡提供檢查與引導（偵測到 git 還在用密碼就提示改用認證管理員），不替使用者決定。

## 需要真機驗證的項目（第一期）

測試無法開真的視窗、也沒有第二個 Windows 帳號，以下要在真機上由人驗證：

1. 安裝後 ASN 資料夾內有 `asn-askpass.exe`；設定頁「視窗」分類看得到「密碼小幫手」段落，「複製路徑」按鈕有用。
2. 在新開的終端機執行 `setx GIT_ASKPASS "<路徑>"` 後重開終端機，對需要密碼的 https 倉庫執行 `git ls-remote`（或 `git push`）：ASN 跳出確認窗，顯示程式（git-remote-https.exe ← git.exe ← …）、工作資料夾、提示文字；輸入後 git 成功；按取消時 git 失敗並顯示中文原因。
3. 關掉 ASN 後再執行同樣的指令：不跳任何視窗，git 立刻失敗並顯示「ASN 沒有在執行」。
4. 確認窗放著不動 2 分鐘會自動關閉並取消；同時開兩個終端機同時要密碼，會一個接一個跳窗。
5. 確認窗在 ASN 縮到系統匣時也會跳到最上層並取得焦點；視窗關閉鈕等同取消。
6. ssh：設 `SSH_ASKPASS` 與 `SSH_ASKPASS_REQUIRE=force` 後，連需要密碼的主機，確認窗出現且能登入。
