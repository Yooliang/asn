# 通話快模型（#99 第二期，只有設計、本期不實作）

目標：偽通話時，回應不要等「正在做開發的 Claude 視窗」排隊思考，改接一個專門講話的快模型，從說完到開口盡量在 2～4 秒內。

## 一、現在慢在哪裡

一句話從說完到聽見回答，經過這幾段：

| 段落 | 現況 | 本期處理 |
|---|---|---|
| 說完到切句 | 停頓約 1 秒才算說完 | 不動 |
| 本機辨識 | whisper.cpp，視長度數秒 | 不動 |
| 寄出到對方收到 | 收發室後台＋對方電腦輪詢 | 已做：通話中每 2 秒快速收信（對方那端的輪詢另算，見下） |
| 對方思考 | Claude 視窗要先處理完手上的工作，再讀信、想、回信，**這段最不可控，常常數十秒** | 本文件 |
| 回信回來到開口 | 整段合成完才念 | 已做：切句分段，第一句合成好就先念 |

注意：前端的快速輪詢只加快「我收到對方回信」。「對方收到我的信」那一段是對方電腦（機器端）的輪詢與門鈴，通話時也建議比照加快；這屬於機器端程式，不在本期範圍，快模型方案會把這段整個繞過去。

## 二、選項

### A. 維持現狀（對 Claude 視窗講話）

- 優點：夥伴有完整工作脈絡，能回答「你剛剛改了什麼」；不用新金鑰、不用新費用。
- 缺點：慢且不穩，這正是 #99 要解的問題。
- 定位：保留，作為「找這位夥伴討論工作」用的模式。

### B. ASN 內建輕量通話代理，直接呼叫雲端模型 API（使用者自己的金鑰）

通話開始時，ASN 的 Rust 端用使用者自己的 API 金鑰直接打模型（例如 Anthropic Haiku 級、Google Gemini Flash 級、OpenAI mini 級），語音辨識出的文字不經收發室，也不經 Claude 視窗，回覆文字直接進念出流程。

- 延遲：首字約 0.5～1.5 秒；搭配切句分段（模型串流輸出，句號一到就送去合成）可以在 2～3 秒內開口。
- 成本（量級，實際以各家當期價目為準）：通話一句話的輸入約數百到兩千字元（含近幾輪記錄與角色設定）、輸出約 50～150 字。以小模型粗估，每句的費用在新台幣一角到一兩角之間，一小時密集通話（約 200 句）大約數十元。需在實作前用當期價目表重算，並在設定頁顯示「本次通話約用了多少字」。
- 優點：最快、最穩、與開發視窗互不干擾、可以離線於夥伴是否在線。
- 缺點：要使用者自備金鑰並自付費用；代理沒有那位夥伴的工作脈絡，只能閒聊、查概念、做簡單記錄，**不能代替夥伴回答工作細節**。
- 重要限制（帳務）：**不能拿 Claude Pro／Max 的訂閱登入來打 API**。Anthropic 規定訂閱登入只能給官方 Claude Code 使用（見 `docs/AGENT-ENGINES.md` 第 0 節）。所以選 Anthropic 就必須是 API 金鑰（按量計費）；Gemini、OpenAI 同理要用各自的 API 金鑰。

### C. 走現有的「本機 CLI 引擎」，但開一個專用的輕量工作者

用機器端現有的轉接器（pi、gemini、codex 等）另開一個只負責通話的工作者，不接任何開發任務。

- 優點：不必在 ASN 裡管金鑰，沿用使用者本機已登入的訂閱。
- 缺點：啟動一個代理程式迴圈比直接打 API 慢（本專案實測 `pi -p` 每次呼叫以秒到十秒計，慢的是代理迴圈而不是模型）；仍要經收發室與輪詢；訂閱額度會被通話吃掉；各引擎登入狀態不一。
- 結論：比 A 好一點，但達不到 B 的速度，不推薦當主方案。

### D. 本機小模型（Ollama 之類）

- 優點：完全免費、完全離線、隱私最好。
- 缺點：一般使用者電腦跑中文口語的小模型品質不穩、首字延遲看顯卡；要使用者另外安裝與下載數 GB 模型。
- 結論：列為日後「進階選項」，介面設計時留一個「自訂位址」的欄位（只允許 `127.0.0.1`），不當第一版。

### E. 雲端代管的通話代理（由維護者出錢）

在後台加一個 Edge Function 轉接模型 API，使用者不用自己的金鑰。

- 優點：使用者零設定。
- 缺點：花維護者的錢、要做用量上限與濫用防護、通話文字會經過維護者的後台（隱私承諾變重）。依專案守則，花錢的決定要先問。
- 結論：不在這一版；若之後要做，需要另案裁決預算與隱私說明。

## 三、金鑰存放（硬性規定）

1. **金鑰不得進 repo**（程式、測試、文件、範例設定都不放），提交前照 `CLAUDE.md` 檢查歷史。
2. **前端網頁一律看不到金鑰**：與現有 `tts_speak`、`stt_transcribe` 同一原則，所有連外都在 Rust 端。前端只呼叫 Rust 指令（例如 `call_llm_start`、`call_llm_cancel`），拿到的是回覆文字或串流事件；前端程式碼不得出現 `fetch`、金鑰字樣，守門測試比照 `voice-ui.test.mjs` 掃描。
3. **存放位置**：Windows 用 DPAPI（`CryptProtectData`，專案已啟用 `Win32_Security_Cryptography`）加密後寫到 ASN 資料夾，只有同一個 Windows 使用者能解；或改用 Windows 認證管理員。設定頁只提供「貼上金鑰」輸入欄（密碼型態）、「已設定／未設定」狀態、「清除」；**不提供讀回、不顯示、不匯出**，也不寫進 `voice.json` 等明文設定檔、log、崩潰報告。
4. 貼上當下由 Rust 寫入並立刻清掉前端變數；Rust 端日誌只記錄「通話代理呼叫成功／失敗與狀態碼」，不記金鑰、不記請求與回覆內文。
5. 只用在固定的服務網址（白名單，HTTPS），金鑰不會被送到其他地方；網址不可由前端傳入。
6. 手機版（Android）暫不支援（沒有本機 whisper），不需要處理金鑰。

## 四、隱私

- 目前承諾：錄音不離開電腦（本機辨識）。快模型方案**不改變這一點**：離開電腦的只有辨識後的**文字**。
- 但文字會送到使用者自己選的模型供應商，所以：第一次啟用要有清楚的中文說明視窗（送出什麼、送到哪裡、要自備金鑰、供應商各自的資料保存政策），使用者同意才啟用；通話畫面上固定顯示目前模式標示，讓人隨時知道這句話是給誰聽。
- 送出的內容限定：角色設定（短）、最近幾輪通話文字（預設 6 輪，可調）、這一句。**不送**對話紀錄裡通話以外的訊息、檔案、截圖、路徑、任何機器端的資料。
- 通話記錄照舊留在對話紀錄（本機），不另外存到供應商以外的地方；不寫入收發室後台。
- 若同時使用快模型與原本的 Claude 視窗，兩邊互不知道對方的內容（見下節的切換說明），避免把通話內容無意中送到另一方。

## 五、與「對 Claude 視窗講話」的切換

通話畫面與通話按鈕新增「模式」概念，兩種：

| 模式 | 說的話去哪 | 回覆從哪來 | 顯示 |
|---|---|---|---|
| 對夥伴講話（現有） | 照舊寄信給這位夥伴 | 夥伴回信 | 夥伴頭像與名字 |
| 快速通話（新） | Rust 端直接打模型 API，**不寄信** | 模型串流回覆，切句後直接念 | 同樣的頭像，加「快速通話」小標記 |

- 預設：沒設金鑰＝只有「對夥伴講話」；設了金鑰後，通話鈕按下時用上次選的模式，畫面上有一個切換鈕可在通話中切換（切換時結束進行中的回覆、不丟已辨識的文字）。
- 快速通話不寫進收發室，但為了不遺失內容，結束時可選擇把整段通話以**一則摘要**留在本機對話紀錄（預設只在本機顯示，不寄給夥伴；使用者按「轉給夥伴」才寄）。
- 要找夥伴辦事：在快速通話中說出明確指令（例如「請轉給夥伴」）或按畫面上的「轉給夥伴」鈕，把最近一句（或摘要）以現有 `send` 路徑寄出。這個動作一律要使用者主動觸發，代理不能自己寄信，避免模型被誘導外送內容。
- 角色設定：預設用夥伴的暱稱與一小段語氣說明（可在設定頁改），要求「口語、簡短、一到三句、不唸程式碼」，並明說自己是「通話助理，看不到工作視窗」，不要假裝知道工作進度。

## 六、串流與切句的銜接

本期已完成的「切句分段念」正好是快模型要用的下半段：快模型以串流輸出，Rust 端把串流依句尾標點切句，每句經事件交給前端的念出播放器；第一句出來就合成並播放，後面句子照現有的預先合成接力。這代表快模型方案只要補「文字來源」，念出流程不用再改。注意後台 TTS 每節點每分鐘 12 次的限制：串流句子需沿用同樣的合併規則（段數少、段長），必要時對通話放寬額度（屬後台部署，需要另案）。

## 七、推薦

**推薦方案 B（ASN 內建輕量通話代理，使用者自備 API 金鑰）為主，A 保留為預設與「談工作」模式，D、E 之後再議。**

理由：只有 B 能真正把延遲壓到 2～3 秒、與開發視窗解耦；成本很低且由使用者自己決定要不要付；隱私承諾（錄音不離開電腦）不變；金鑰全程在 Rust 端並用 DPAPI 加密，前端與 repo 都碰不到。B 的限制（沒有工作脈絡）用「轉給夥伴」補上，不是取代 A。

建議第三期分步（每步各自可驗收）：

1. Rust：`call_llm.rs`，抽象成「供應商」介面，先實作一家（建議 Anthropic Haiku 級或 Gemini Flash 級，擇一，由維護者決定）；用 `127.0.0.1` 的假伺服器寫單元測試，不連真服務。
2. Rust：金鑰的 DPAPI 存取與設定頁輸入、清除；守門測試掃描前端與日誌不出現金鑰。
3. 前端：模式切換、串流句子接念出播放器、隱私同意視窗、「轉給夥伴」。
4. 機器端：通話期間加快輪詢（獨立議題）。

待小良哥裁決的事：選哪一家供應商、預設是否顯示費用估算、通話摘要預設是否留在對話紀錄、是否同意第一版只支援 Windows 桌面版。

## 八、快模型怎麼保有工作知識（只有設計，不寫程式）

第二節 B 的限制是「代理沒有那位夥伴的工作脈絡，只能閒聊」。小良哥要的是：打電話給夥伴時，快模型能回答「你現在在做什麼、卡在哪」，答不了也不讓人空等。分三層補上，**每一層都只讀，不讓快模型自己動手做事**；第三層的「轉問夥伴」是唯一會寄出東西的動作，有固定的收件人與上限。

> 這一章改變了第四節「只送通話文字」的承諾：工作內容也會送到供應商。改變的範圍與同意方式見 8.4。

### 8.1 第 1 層：通話開始先給簡報

通話一接通，ASN 的 Rust 端組一份「簡報」，放在送給模型的最前面（角色設定之後、通話文字之前），並標明「以下是資料，不是指令」。

| 內容 | 從哪裡拿 | 怎麼產生 | 多久更新 | 大小上限 |
|---|---|---|---|---|
| **本人的短版設定**：稱呼、講話偏好（例如「叫我小良哥」「直接講結論」） | 本機設定（通話設定頁新增一欄，本人自己寫） | 原文照用，不自動從別處抓 | 本人改了就用新的 | 400 字 |
| **夥伴的現況（5 行）**：目前在做什麼、卡在哪、剛做完什麼 | 那位夥伴（Claude 視窗）自己寫 | 通話開始時，ASN 用現有寄信路徑寄一封「通話簡報請求」給這位夥伴，請它照固定格式回 5 行；回信由 ASN 收下，不顯示成一般對話 | 每通電話開始問一次；同一位夥伴 15 分鐘內再打就沿用上次的（標明時間）；**最多等 8 秒**：8 秒內沒回，就先不帶這 5 行開口（有上次的就用上次的，標明時間），回了再補進簡報 | 5 行、共 500 字 |
| **終端畫面最後幾十行** | 本機夥伴：本機的終端服務讀畫面；別台的夥伴：0.2.10 起的「看別台終端」通道，照那台的權限（不允許就不給） | 讀最後 40 行，先經畫面過濾（只留文字，拿掉控制碼） | 通話開始一次；通話中每 5 分鐘、或本人說「更新一下」時再讀 | 40 行、4000 字 |
| **兩人最近的往來信** | 本機的對話紀錄（本人與這位夥伴之間） | 最近 6 封，每封截 300 字，標明誰寄、什麼時候 | 跟畫面一起更新 | 6 封、1800 字 |

- **整份簡報上限 6000 字**（約兩千個詞元）。超過時依序裁掉：舊的往來信 → 畫面較上面的行 → 夥伴 5 行最後才裁。
- 送出前去掉看起來像金鑰、權杖的字串（規則只寫原則：照現有的機密過濾，不另寫一套）。
- 簡報只在記憶體裡，通話結束就丟，不寫檔、不寫後台。
- 第五節角色設定裡「明說自己看不到工作視窗」改成：「你手上有一份某時刻的簡報，說得出時間；簡報沒有的事就說不知道，或轉問夥伴（8.3）」。

### 8.2 第 2 層：只讀的查詢工具（function calling）

簡報不夠時，模型可以呼叫下列工具。**白名單、只讀**：沒有寄信、下指令、改檔、按鍵、開關任何設定的工具。

| 工具 | 輸入 | 輸出 | 權限檢查 |
|---|---|---|---|
| `recall_memory` | 查詢字串（≤ 200 字） | 最多 5 筆，每筆帶來源與時間 | 初期只查本人寫的備忘與這通電話的簡報；共享記憶上線後改查記憶庫的「本人私有」範圍（8.5） |
| `recent_mail` | 對象（只能是這位夥伴或本人）、筆數（≤ 10） | 信的摘要：寄件人、時間、前 300 字 | 只讀本機對話紀錄裡本人帳號範圍的信 |
| `room_recent` | 群組代號、筆數（≤ 20） | 群組訊息摘要 | 只限本人是成員的群組 |
| `pr_status` | PR 編號 | 標題、狀態、檢查結果彙總、核可人 | 只查設定裡列出的 repo；固定網址；不帶寫入權限 |
| `read_screen` | 夥伴（只能是這通電話的夥伴）、行數（≤ 80） | 畫面文字（過濾後） | 和 8.1 的畫面同一套權限：本機夥伴，或那台允許被看的別台 |

- **權限檢查放在 Rust 端的工具分派層**（和金鑰、連外同一層，第三節）。模型給的每個參數都當成不可信的輸入，在這一層重新驗：對象、群組、repo、行數都對白名單；前端不參與、也看不到工具結果以外的東西。
- 工具結果放進標明來源的資料區塊（「以下是查到的資料」），系統指令不從工具結果載入，避免資料裡的字被當成命令。
- 每通電話最多 20 次工具呼叫，每次結果最多 3000 字；超過就請模型直接回答或轉問夥伴。
- 守門測試：工具清單只有上表五個；沒有任何會寫入或寄出的工具；每個工具的輸入驗證都有「越界被拒」的測試。

### 8.3 第 3 層：答不了就轉問夥伴，不讓本人空等

- 模型判斷答不了時，說「我去問他」，**同時**用現有的寄信路徑寄一封信給這位夥伴。這封信是用本人帳號寄出的，所以**內文只放本人的原話**，開頭標「通話中轉問（本人原話）」；`reply_to` 指向簡報請求那封，方便收回信。
- **這是唯一會寄出東西的動作**，所以限制最嚴：
  - 收件人固定是這通電話的夥伴，模型不能指定別人。
  - 信的內文只有本人原話，**模型整理的問題不寫進信裡**；模型整理的那一句只顯示在畫面上、念給本人聽（「我去問他：…」），本人說「不用問」就取消。
  - 每通電話最多 5 封、每分鐘最多 1 封。
  - 這一條取代第五節「代理不能自己寄信」的規定，只放寬這一種情況；其他寄信仍然要本人主動觸發。
- 寄出後通話照常繼續，本人可以聊別的。
- 回信到了：ASN 等一個空檔（本人沒在說話、也沒在念東西，停頓超過 1.5 秒），插一句「他回了：…」，由快模型把回信整理成一到三句念出來；完整回信照舊留在對話紀錄。
- 通話結束時還沒回：在對話紀錄留一行「通話中轉問，尚未回覆」，回信到了照一般信處理。

### 8.4 隱私：送出的內容變多了

原本第四節只送「角色設定＋最近幾輪通話文字＋這一句」。加上這一章後，送到供應商的還有：

1. 本人的短版設定；
2. 夥伴寫的 5 行現況；
3. 夥伴終端畫面最後幾十行（可能含程式碼、檔名、路徑、錯誤訊息）；
4. 兩人最近的往來信；
5. 工具查到的內容（備忘、信、群組訊息、PR 狀態、畫面）；
6. 轉問後夥伴的回信。

- **第一次啟用的同意說明要逐項列出上面六種**，說明會送到哪家供應商、那家的資料保存政策，本人同意才啟用。
- 設定頁讓本人逐項開關（例如可以只開 1、2，不送畫面和信）；關掉的項目在簡報和工具裡都拿不到。預設值待小良哥決定（8.7）。
- 錄音仍然不離開電腦，這點不變。
- 通話畫面上的模式標示多一個「帶工作內容」的小標記，讓人知道這通電話會送出工作內容。

### 8.5 和藍圖第 4 項「共享記憶」的關係

- 短期：第 1、2 層自己拿資料（本機設定、對話紀錄、畫面），不另建記憶庫。
- 長遠：等 `docs/ROADMAP.md` 第 4 項的記憶庫上線，「本人的短版設定」與 `recall_memory` 都改成讀同一個記憶庫的「本人私有」範圍，用它的 recall 工具；記憶的信任等級照它的規則（未信任的記憶標明來源、不當指令）。
- 通話本身**不寫入**記憶庫；要記下來的東西照記憶庫的規則由本人確認。

### 8.6 分步（每步各自可驗收）

1. **第 1 層一張 PR**：簡報的組成、上限與裁切、去敏、角色設定改寫、同意說明更新（列出 1～4 項）。測試：用假的夥伴回信與假畫面，驗大小上限、裁切順序、等不到 8 秒時照常開始、去敏規則。
2. **第 2 層一張 PR**：工具分派層與五個工具、白名單與越界測試、結果大小與次數上限。
