# 偽通話（#99）第一期設計

目標：在對話視窗按「通話」，用說的跟 AI 夥伴對話，回信自動念出來，再按掛斷結束。不新增任何後台、Rust 指令或寄信管道。

## 使用流程

1. 對話上方的大按鈕列（#40）新增「通話」鈕（夥伴在線、這個視窗有語音功能才出現）。
2. 按下後蓋出通話畫面：大頭像、狀態文字、通話計時、音量條、最近一句「你說的」與「對方回的」字幕、靜音、掛斷。
3. 循環：聆聽 → 說完停頓約 1 秒自動收一句 → 本機辨識 → 寄出 → 「對方思考中…」→ 回信到達 → 念出 → 念完回到聆聽。
4. 掛斷（或切走分頁、換夥伴、關掉面板）就結束，回到一般模式。通話中所有來回照常留在對話紀錄。

## 語音辨識：沿用本機 whisper，不用 Web Speech API

- 現有「語音輸入」（`docs/VOICE.md`）已經有 WebView2 麥克風錄音（`mic.mjs`）、人聲偵測（`voice-activity.mjs`）、本機 whisper.cpp 辨識（Rust 指令 `stt_transcribe`）與幻覺過濾簡轉繁（`stt-text.mjs`）。通話直接重用，聲音不離開這台電腦。
- 不選 WebView2 的 Web Speech API：它在 Windows 上會把聲音送到微軟雲端、中文辨識與可用性不穩，也與「語音輸入不上傳」的承諾不一致。
- 辨識不可用時的中文提示：還沒下載引擎或模型 → 不開麥克風，顯示對話區上方現成的下載提示；麥克風沒授權、找不到、被占用 → 沿用 `micErrorText` 的說明；單句辨識失敗 → 通話畫面顯示「這句沒辨識成功」，不中斷通話；辨識引擎中途消失 → 通話結束並說明。

## 切句（`call-vad.mjs`）

麥克風一直開著，每塊（約 0.1 秒）算 RMS：持續 0.15 秒以上超過門檻＝開始說話；開始後安靜達 1.0 秒＝一句結束（一句最長 30 秒強制切）。門檻＝底噪的 3 倍，夾在 0.012～0.06 之間，底噪只在沒人說話時追蹤。開頭多留 0.5 秒避免吃掉字頭。切出來的句子再過原本 `analyze`（沒有真人聲就不送，擋咳嗽、碰桌子）與幻覺過濾，才送去辨識。已知限制：底噪持續高於 0.012（很吵的環境）時會一直被當成在說話，最長 30 秒切一次，辨識時會被人聲檢查擋掉。

## 寄出

只走對話區原本的 `send` 事件（分開模式 → 名單視窗樞紐 → `core.send`，整合模式同理），所以本人簽章與多設備（#108 `as_person`）全都沿用，通話程式碼裡沒有任何寄信指令。每封信前面附一行 `（語音通話中，請簡短口語回答）`，讓回覆適合念出來；這行會一起出現在對話紀錄裡（決定：寧可每封都帶，避免雲端代理沒有上下文時忘記）。

## 念出回覆

- 用現有 `TtsPlayer` 與 `tts_speak`（經收發室後台與 Cloudflare 轉接，金鑰在 Rust）。每次通話不另外呼叫別的服務。
- 回信偵測：對話區的 `log` 一變就交給通話，通話開始時已存在的訊息先記起來不念，之後新的「對方」訊息才念；同一則不重念。
- 太長的回信只念前 300 字（句子邊界截斷），其餘照常在對話裡。
- 後台對 TTS 有每分鐘 12 次的限制；超過會顯示「念不出來」並回到聆聽，不會卡住。

## 不聽到自己

- 念出期間完全不收音（不做插話，插話是選做，第一期不做），念完後再等 0.6 秒回音保護才開始聽。
- 靜音：不收音、丟掉說到一半的那一句。
- 等回信的時候仍在聽，可以接著說下一句。

## 避免雙重念

設定的「收到新訊息自動念」（預設關）由名單視窗的語音實例負責。通話中要暫停它，否則同一則回信念兩次：整合模式直接看同視窗的 `isCallActive()`；分開模式由對話視窗每 20 秒廣播 `asn:call`（`call-beats.mjs`），名單視窗 60 秒沒聽到就當作結束（視窗被直接關掉也不會卡住）。

## 其他規則

- 同時只能一個通話；通話中麥克風輸入鈕讓路（提示「通話中，不能同時用語音輸入」），語音輸入進行中也不能開始通話。
- 對方離線時不顯示通話鈕（信只會留在收發室，通話等不到回覆）。
- 狀態文字：準備麥克風…／聆聽中…請說話／辨識中…／對方思考中…／對方說話中…；寄出後 3 分鐘沒回信就不再顯示「思考中」。
- UI 全中文，字幕以純文字輸出（不解析網頁語法）。
