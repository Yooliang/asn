# 版本規劃

> 由領隊（asn真）維護。**以 GitHub 里程碑為準**，這份是給人一眼看的總表；每次重排、每次發版後更新。最後更新：2026-11-21。
> 上一版是 0.1.x 時期的表，已作廢；舊內容在 git 歷史裡。


## 規則（擁有者 11-19～11-20 定）

- **一個版本號只放一件改動**，才能單獨發、單獨驗。
- **先做好的先發**：發版都從 main 出，合併順序＝版本順序；後面的做好了，就跟前面還沒做好的對調。版號不跳號。
- **只有不會進 App 的不佔版本**：測試、CI、文件、調查（里程碑「不佔版本」）。改到 App 程式碼的，就算是內部重構也佔一個版本號。
- **一張單定好範圍就不再加料**；新想法另開單、排新版本。
- 擁有者每提一件新事，開下一個版本號排進去。
- 穩定性排在介面前面；同性質的排在相鄰版本（11-20 金魚審過）。
- 需要擁有者驗的項目不擋發版，累積成清單一次給他。
- 不進 App 的小單一審就能合；進 App 的版本項、動到金鑰或發版權限的維持兩審（11-21 #4602）。
- 里程碑號是排隊位置；實際發版照完成順序用下一個連續號，發的時候把單改掛到那個號（11-21）。
