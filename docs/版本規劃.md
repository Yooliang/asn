# 版本規劃

> 由領隊（asn真）維護。**以 GitHub 里程碑為準**，這份是給人一眼看的總表；每次重排、每次發版後更新。最後更新：2026-11-22。
> 2026-11-21 擁有者定：開發進度與發版進度拆開、分別維護；開發順序只用單號／PR 號，不綁版號。
> 上一版是 0.1.x 時期的表，已作廢；舊內容在 git 歷史裡。


## 規則（擁有者 11-19～11-21 定）

- **開發順序＝單號由小到大，先開的先做**；夥伴領最前面還沒人領、依賴已滿足的那張。只有正在發生的資料遺失／當機，或擁有者明講，才提前，並記在下方「調整紀錄」。
- **依賴**：單上寫「依賴 #A」，A 還沒合進 main 之前 B 不能領。一件事要分幾步才成立的（例如修補→建新版終端→換用），算同一張，拆成幾個 PR，最後一個合了才算完成。
- **版號在發版時才給**，照發的先後連號遞增（release-tag 本來就是現版號加一）。哪張先完成、合進 main，就跟著下一個版號發；某一張卡住，只是它自己晚發，不擋別人。不預先綁版號，不再有跳號、對調、整串挪號。
- **發版紀錄**：每次發版後，在下方「已發」表新增一列：版號｜日期｜包含的單｜一句重點。
- **只有不會進 App 的不佔版本**：測試、CI、文件、調查（里程碑「不佔版本」）。改到 App 程式碼的，就算是內部重構也算一個發版項目。
- **一張單定好範圍就不再加料**；新想法另開單，排在最後。
- 穩定性排在介面前面；同性質的放在相鄰（11-20 金魚審過）。
- 需要擁有者驗的項目不擋發版，累積成清單一次給他。
- 不進 App 的小單一審就能合；進 App 的項目、動到金鑰或發版權限的維持兩審（11-21 #4602）。
- GitHub 上舊的 0.2.N 里程碑不再代表版號，之後收掉；以本文件為準。
